3. 按照 Dijkstra 算法的策略，依次给出 R1 到图中各个 `192.1.x.x` 网络的最短路径及费用。

### 第（2）问：设计保存 LSI 的链式存储结构

**考查知识点：** 链式存储、多重数据类型、结构体、联合体（`union`）、链表。

#### 1. 设计思路

根据题目给出的 LSI 表，每个路由器需要维护多种类型的链路状态信息：

- **链路信息（Link）：** 记录所连接路由器的 Router ID、本地接口 IP。
- **网络信息（Net）：** 记录直连网络的网络前缀和子网掩码。
- **度量值（Metric）：** 记录对应链路或网络的费用。

由于链路信息和网络信息的数据成员不同，可以分别定义 `LinkNode` 和 `NetNode` 两种结构，再使用 `union` 将两种类型的数据放在同一个通用结点中。通过 `Flag` 标识当前结点存储的是哪一种信息。

每个路由器设置一个头结点，头结点指向该路由器的链路状态信息链表；各信息结点通过 `next` 指针连接。

#### 2. 数据结构定义

```c
// 链路节点结构
struct LinkNode {
    unsigned int ID;        // 所连接路由器的 Router ID
    unsigned int IP;        // 本地接口 IP 地址
};

// 网络节点结构
struct NetNode {
    unsigned int Prefix;    // 网络前缀
    unsigned int Mask;      // 子网掩码
};

// 通用节点结构：使用 union 支持多态
struct Node {
    int Flag;               // 节点类型标识：1-链路节点，2-网络节点
    union {
        struct LinkNode LNode;
        struct NetNode NNode;
    } Data;
    unsigned int Metric;    // 度量值
    struct Node *next;      // 指向下一个节点的指针
};

// 路由器头节点结构
struct HeadNode {
    unsigned int RouterID;  // 路由器标识
    struct Node *link;      // 指向节点链表的头指针
    struct HeadNode *next;  // 指向下一个路由器的指针
};
```

#### 3. 各字段含义

| 字段 | 含义 |
|---|---|
| `LinkNode.ID` | 所连接路由器的 Router ID |
| `LinkNode.IP` | 本地接口 IP 地址 |
| `NetNode.Prefix` | 直连网络的网络前缀 |
| `NetNode.Mask` | 子网掩码 |
| `Node.Flag` | 区分当前结点是链路信息还是网络信息 |
| `Node.Data` | 使用联合体保存链路信息或网络信息 |
| `Node.Metric` | 当前链路或直连网络的度量值 |
| `Node.next` | 指向同一路由器的下一条链路状态信息 |
| `HeadNode.RouterID` | 路由器的 Router ID |
| `HeadNode.link` | 指向该路由器链路状态信息链表的头指针 |
| `HeadNode.next` | 指向下一个路由器头结点 |

其中，`Flag=1` 表示 `Data` 中存储的是 `LinkNode`；`Flag=2` 表示存储的是 `NetNode`。由于 `union` 的成员共用同一段存储空间，因此必须通过 `Flag` 判断当前应读取哪一种数据。

#### 4. 链式存储结构示意

整体结构分为两层：

1. 路由器头结点链表：依次保存 R1、R2、R3、R4。
2. 每个路由器头结点下面的信息链表：保存该路由器的 Link 信息和 Net 信息，每个信息结点包含对应的 Metric。

```text
路由器头结点链表

R1                         R2
│                          │
link                       link
│                          │
▼                          ▼
[Link: R2, Metric=3]       [Link: R1, Metric=3]
        │                          │
        ▼                          ▼
[Link: R3, Metric=2]       [Link: R4, Metric=4]
        │                          │
        ▼                          ▼
[Net: 192.168.1.0/24, 1]   [Net: 192.168.6.0/24, 1]
        │                          │
       NULL                       NULL


R3                         R4
│                          │
link                       link
│                          │
▼                          ▼
[Link: R4, Metric=6]       [Link: R3, Metric=6]
        │                          │
        ▼                          ▼
[Link: R1, Metric=2]       [Link: R2, Metric=4]
        │                          │
        ▼                          ▼
[Net: 192.168.5.0/24, 1]   [Net: 192.168.7.0/24, 1]
        │                          │

```

上图中 `Link` 结点对应 `Flag=1`，`Net` 结点对应 `Flag=2`。每个信息结点的 `Metric` 保存题目表格中相应的费用。

**注意：** 题目图片中的结构设计采用的是“路由器头结点链表 + 通用信息结点链表”，而不是普通图的标准邻接表。答题时应突出 `LinkNode`、`NetNode`、`union`、`Flag`、`Metric` 和两个层次的 `next` 指针。

### 第（3）问：使用 Dijkstra 算法求 R1 到各网络的最短路径及费用

**考查知识点：** Dijkstra 单源最短路径、距离更新、路径还原。

#### 1. 建立带权图

顶点：

\[
V=\{R1,R2,R3,R4,N1,N2,N3,N4\}
\]

边及权值：

\[
\begin{aligned}
&R1-R2=3,\quad R1-R3=2\\
&R2-R4=4,\quad R3-R4=6\\
&R1-N1=1,\quad R2-N2=1\\
&R3-N3=1,\quad R4-N4=1
\end{aligned}
\]

其中：

- \(N1=192.168.1.0/24\)
- \(N2=192.168.6.0/24\)
- \(N3=192.168.5.0/24\)
- \(N4=192.168.7.0/24\)

#### 2. Dijkstra 算法基本思想

设：

- \(S\)：已经确定最短路径的顶点集合。
- \(dist[v]\)：当前从源点 R1 到顶点 \(v\) 的最短距离估计值。
- \(prev[v]\)：当前最短路径中，顶点 \(v\) 的前驱顶点。

初始化：

\[
dist[R1]=0
\]

其他顶点：

\[
dist[v]=\infty
\]

重复执行：

1. 从尚未确定最短路径的顶点中，选择 \(dist\) 最小的顶点 \(u\)。
2. 将 \(u\) 加入集合 \(S\)。
3. 用 \(u\) 更新其尚未确定的邻接顶点：
   \[
   \boxed{dist[v]=\min(dist[v],dist[u]+w(u,v))}
   \]
4. 直到所有可达顶点的最短路径均确定。

本题边权均为非负数，可以使用 Dijkstra 算法。

#### 3. 初始化

源点为 R1：

\[
S=\{R1\}
\]

R1 的直接邻接点：

- 到 R2：费用3。
- 到 R3：费用2。
- 到 N1：费用1。

其余顶点暂时不可达。

| 顶点 | R1 | R2 | R3 | R4 | N1 | N2 | N3 | N4 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 初始距离 | 0 | 3 | 2 | \(\infty\) | 1 | \(\infty\) | \(\infty\) | \(\infty\) |
| 前驱 | — | R1 | R1 | — | R1 | — | — | — |

#### 4. 逐轮计算

**第1轮：选择 N1**

当前未确定顶点中距离最小的是 N1：

\[
dist[N1]=1
\]

将 N1 加入 \(S\)。N1 只有 R1 一个邻接点，而 R1 已经确定，因此没有新的距离更新。

\[
S=\{R1,N1\}
\]

**第2轮：选择 R3**

当前距离最小的是 R3：

\[
dist[R3]=2
\]

将 R3 加入 \(S\)，检查其邻接点：

- R1：已经确定。
- R4：经过 R3 的距离为：
  \[
  dist[R3]+w(R3,R4)=2+6=8
  \]
  更新 \(dist[R4]=8\)，前驱为 R3。
- N3：经过 R3 的距离为：
  \[
  dist[R3]+w(R3,N3)=2+1=3
  \]
  更新 \(dist[N3]=3\)，前驱为 R3。

\[
S=\{R1,N1,R3\}
\]

**第3轮：选择 R2 或 N3**

此时：

\[
dist[R2]=3,\quad dist[N3]=3
\]

二者并列最小，可以任选一个先加入。这里先选择 R2。

将 R2 加入 \(S\)，检查其邻接点：

- R1：已经确定。
- R4：原距离为8，经 R2 到达 R4 的距离为：
  \[
  dist[R2]+w(R2,R4)=3+4=7
  \]
  因为 \(7<8\)，更新：
  \[
  dist[R4]=7,\quad prev[R4]=R2
  \]
- N2：经 R2 到达 N2 的距离为：
  \[
  dist[R2]+w(R2,N2)=3+1=4
  \]
  更新：
  \[
  dist[N2]=4,\quad prev[N2]=R2
  \]

\[
S=\{R1,N1,R3,R2\}
\]

**第4轮：选择 N3**

\[
dist[N3]=3
\]

将 N3 加入 \(S\)。N3 的另一端是 R3，R3 已经确定，因此不更新其他距离。

\[
S=\{R1,N1,R3,R2,N3\}
\]

**第5轮：选择 N2**

\[
dist[N2]=4
\]

将 N2 加入 \(S\)。N2 的另一端是 R2，R2 已经确定，因此不更新其他距离。

\[
S=\{R1,N1,R3,R2,N3,N2\}
\]

**第6轮：选择 R4**

当前未确定顶点中：

\[
dist[R4]=7
\]

将 R4 加入 \(S\)，检查其邻接点：

- R3：已经确定。
- R2：已经确定。
- N4：经过 R4 的距离为：
  \[
  dist[R4]+w(R4,N4)=7+1=8
  \]
  更新：
  \[
  dist[N4]=8,\quad prev[N4]=R4
  \]

**第7轮：选择 N4**

\[
dist[N4]=8
\]

将 N4 加入 \(S\)，算法结束。

#### 5. Dijkstra 过程汇总表

表中距离为每轮更新后的当前距离；“本轮确定顶点”表示本轮加入集合 \(S\) 的顶点。

| 轮次 | 本轮确定顶点 | R1 | R2 | R3 | R4 | N1 | N2 | N3 | N4 |
|---:|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 初始化 | R1 | 0 | 3 | 2 | \(\infty\) | 1 | \(\infty\) | \(\infty\) | \(\infty\) |
| 1 | N1 | 0 | 3 | 2 | \(\infty\) | 1 | \(\infty\) | \(\infty\) | \(\infty\) |
| 2 | R3 | 0 | 3 | 2 | 8 | 1 | \(\infty\) | 3 | \(\infty\) |
| 3 | R2 | 0 | 3 | 2 | 7 | 1 | 4 | 3 | \(\infty\) |
| 4 | N3 | 0 | 3 | 2 | 7 | 1 | 4 | 3 | \(\infty\) |
| 5 | N2 | 0 | 3 | 2 | 7 | 1 | 4 | 3 | \(\infty\) |
| 6 | R4 | 0 | 3 | 2 | 7 | 1 | 4 | 3 | 8 |
| 7 | N4 | 0 | 3 | 2 | 7 | 1 | 4 | 3 | 8 |

说明：第3轮 R2 与 N3 的距离同为3，二者的确定顺序可以互换，不影响最终最短距离和路径结果。

根据前驱关系：

- N1 的前驱是 R1。
- N2 的前驱是 R2，R2 的前驱是 R1。
- N3 的前驱是 R3，R3 的前驱是 R1。
- N4 的前驱是 R4，R4 的前驱是 R2，R2 的前驱是 R1。

**（1）R1 到 192.168.1.0/24**

路径：

\[

\]

费用：

\[
\boxed{1}
\]

**（2）R1 到 192.168.6.0/24**

路径：

\[
R1\rightarrow R2\rightarrow N2
\]

费用：

\[
3+1=4
\]

\[
\boxed{4}
\]

**（3）R1 到 192.168.5.0/24**

路径：

\[
R1\rightarrow R3\rightarrow N3
\]

费用：

\[
2+1=3
\]

\[
\boxed{3}
\]

**（4）R1 到 192.168.7.0/24**

到达 R4 有两条候选路径：

路径一：

\[
R1\rightarrow R2\rightarrow R4
\]

费用：

\[

路径二：

## 四、核心考点总结

### 1. 网络拓扑图的抽象

网络拓扑通常可以抽象为图：

- 设备或网络节点：顶点。
- 链路：边。
- 链路费用、距离或 Metric：边权值。

当链路具有方向性时，可抽象为有向带权图；本题路由器之间的链路按双向连接处理，因此采用带权无向图表示。

### 2. 邻接表

邻接表适合表示稀疏图，主要由顶点表和边结点组成：

- 顶点表：保存顶点信息和邻接链表头指针。
- 边结点：保存邻接顶点、边权值和下一条边指针。

对于无向图，每条边通常需要在两个端点的邻接链表中各保存一个边结点。

### 3. Dijkstra 算法

Dijkstra 用于求解**带非负权值的图中，一个源点到其他各顶点的最短路径**。

核心公式：

\[
\boxed{dist[v]=\min(dist[v],dist[u]+w(u,v))}
\]

每轮选择当前距离最小且尚未确定的顶点，将其最短距离确定下来，再利用它更新邻接顶点。

常见实现的时间复杂度：

- 邻接矩阵实现：\(O(V^2)\)。
- 邻接表 + 优先队列实现：通常为 \(O((V+E)\log V)\)。

### 4. Dijkstra 与其他最短路径算法的区别

| 算法 | 解决的问题 | 关键特点 |
|---|---|---|
| Dijkstra | 单源最短路径 | 要求边权非负 |
| Floyd | 所有顶点对最短路径 | 动态规划，可处理负权边，但不能有负权回路 |
| Bellman-Ford | 单源最短路径 | 可处理负权边，可检测负权回路 |

## 五、易错点

1. **不要混淆 Router ID、接口 IP 和网络前缀。** Router ID 用于标识路由器；接口 IP 标识本地链路接口；网络前缀表示目的网络。
2. **Metric 是边权，不是 IP 地址。** 计算路径费用时，将经过的各条链路 Metric 相加。
3. **到目的网络还要计算最后一段费用。** 例如到 R4 后，还要加上 R4 到 `192.168.7.0/24` 的 Metric 1。
4. **Dijkstra 每轮选当前未确定顶点中距离最小者。** 不是每次选择边权最小的边。
5. **发现更短路径时必须更新前驱。** 本题 R4 最初通过 R3 得到距离8，后来通过 R2 得到距离7，应更新为经 R2 到达。
6. **本题存在并列选择。** 第3轮 R2 和 N3 的当前距离均为3，可以任选一个先确定，不影响最终结果。
7. **Dijkstra 不适用于存在负权边的一般最短路径问题。** 本题所有 Metric 均为正数，可以使用 Dijkstra。

## 六、考场解题模板

遇到网络拓扑 + Dijkstra 综合题，可以按以下顺序作答：

1. **抽象图：** 将路由器和目的网络作为顶点，将链路作为边，Metric 作为权值。
2. **整理邻接关系：** 从 LSI 表中提取相邻节点及对应费用。
3. **初始化：** 源点距离设为0，直接邻接点设为对应边权，其余设为无穷大。
4. **逐轮选择：** 选择未确定顶点中距离最小的顶点。
5. **松弛更新：**
   \[
   dist[v]=\min(dist[v],dist[u]+w(u,v))
   \]
6. **记录前驱：** 距离变小时同步更新 `prev[v]`。
7. **还原路径：** 从目的顶点沿前驱指针反向回溯至源点。
8. **计算费用：** 将最短路径上所有边的 Metric 相加。

}
