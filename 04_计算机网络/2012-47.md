## 二、题目条件整理

### 1. 已知条件

| 条件 | 内容 |
|---|---|
| 主机 H | IP 地址为 `192.168.0.8` |
| 服务器 S | IP 地址为 `211.68.71.80` |
| 通信协议 | TCP |
| 抓包位置 | 主机 H |
| 题 47-a | 给出 5 个 IP 分组的前 40 字节 |
| 题 47-b | 给出某个 IP 分组在 S 发出时的前 40 字节 |

### 2. 题目要求

1. 判断题 47-a 中哪些 IP 分组由 H 发送；哪些分组完成了 TCP 连接建立过程；哪些分组通过快速以太网传输时需要填充。
2. 根据题 47-a，分析 S 已经收到的应用层数据字节数。
3. 根据题 47-b 与题 47-a 中对应的 IP 分组，计算该 IP 分组从 S 到达 H 经过的路由器数量。

IPv4 首部固定部分为 20 字节。TCP 首部长度由数据偏移字段确定。

| 分组 | IP 总长度 | IP 标识 | TTL | TCP 源端口→目的端口 | TCP 序列号 | TCP 确认号 | TCP 首部长度 | TCP 标志 |
|---|---:|---:|---:|---|---|---|---:|---|
| 1 | `0030H` = 48B | `019BH` | `80H` = 128 | `0BD9H`→`1388H` | `846B41C5H` | 0 | 28B | SYN |
| 2 | `0030H` = 48B | `0000H` | `31H` = 49 | `1388H`→`0BD9H` | `E0599FEFH` | `846B41C6H` | 28B | SYN、ACK |
| 3 | `0028H` = 40B | `019CH` | `80H` = 128 | `0BD9H`→`1388H` | `846B41C6H` | `E0599FF0H` | 20B | ACK |
| 4 | `0038H` = 56B | `019DH` | `80H` = 128 | `0BD9H`→`1388H` | `846B41C6H` | `E0599FF0H` | 20B | PSH、ACK |
| 5 | `0028H` = 40B | `6811H` | `31H` = 49 | `1388H`→`0BD9H` | `E0599FF0H` | `846B41D6H` | 20B | ACK |

\[

\]

## 三、逐问解析

### 第（1）问：判断 H 发送的分组、完成 TCP 连接建立的分组，以及需要以太网填充的分组

#### 1. 考查知识点

- TCP 三次握手
- TCP 端口号、序列号和确认号
- IPv4 总长度
- TCP 首部长度
- 以太网最小帧长与填充

#### 2. 判断哪些分组由 H 发送

先根据 TCP 端口号判断通信方向：

- H 发出的报文：源端口为 3033，目的端口为 5000。
- S 发出的报文：源端口为 5000，目的端口为 3033。

因此：

| 分组 | TCP 源端口 | TCP 目的端口 | 发送方向 |
|---|---:|---:|---|
| 1 | 3033 | 5000 | H → S |
| 2 | 5000 | 3033 | S → H |
| 3 | 3033 | 5000 | H → S |
| 4 | 3033 | 5000 | H → S |
| 5 | 5000 | 3033 | S → H |

所以，由 H 发送的是：

\[
\boxed{1、3、4}
\]

第 2 个分组是服务器返回的 SYN+ACK；第 5 个分组是服务器返回的 ACK。

#### 3. 判断哪些分组完成 TCP 连接建立过程

TCP 使用三次握手建立连接。

**第一次握手：分组 1**

分组 1 的 TCP 标志位为 SYN=1，序列号为：

\[
Seq=846B41C5_H
\]

表示 H 发起连接，并告知服务器自己的初始序列号。

**第二次握手：分组 2**

分组 2 的 TCP 标志位为 SYN=1、ACK=1：

\[
Seq=E0599FEF_H
\]

\[
Ack=846B41C6_H
\]

确认号满足：

\[
846B41C5_H+1=846B41C6_H
\]

说明服务器确认了 H 的 SYN。SYN 会消耗一个序列号。

**第三次握手：分组 3**

分组 3 的 TCP 标志位为 ACK=1：

\[
Seq=846B41C6_H
\]

\[
Ack=E0599FF0_H
\]

其中：

\[
E0599FEF_H+1=E0599FF0_H
\]

说明 H 确认了服务器的 SYN。至此，TCP 三次握手完成。

因此，完成 TCP 连接建立过程的是：

\[
\boxed{1、2、3}
\]

#### 4. 判断哪些分组需要以太网填充

快速以太网最小帧长为 64 字节。以太网帧首部为 14 字节，FCS 为 4 字节，因此最小数据字段长度为：

\[
64-14-4=46\text{ 字节}
\]

IP 分组作为以太网数据字段承载。当 IP 分组长度小于 46 字节时，需要在以太网数据字段末尾填充；填充字节不属于 IP 分组。

判断公式：

\[
\text{填充长度}=\max(0,46-\text{IP分组长度})
\]

逐个分析：

| 分组 | IP 总长度（十六进制） | IP 总长度（十进制） | 是否小于 46B | 填充长度 |
|---|---:|---:|---|---:|
| 1 | `0030H` | 48B | 否 | 0B |
| 2 | `0030H` | 48B | 否 | 0B |
| 3 | `0028H` | 40B | 是 | 6B |
| 4 | `0038H` | 56B | 否 | 0B |
| 5 | `0028H` | 40B | 是 | 6B |

例如分组 3：

\[
46-40=6\text{ 字节}
\]

因此需要填充 6 字节。

需要填充的分组为：

\[
\boxed{3、5}
\]

**注意：** 以太网填充不会改变 IP 首部中的总长度字段。例如分组 3 的 IP 总长度仍为 40 字节，以太网数据字段则补足为 46 字节。

#### 5. 第（1）问最终答案

- 由 H 发送：**1、3、4 号分组**。
- 完成 TCP 三次握手：**1、2、3 号分组**。
- 需要以太网填充：**3、5 号分组**，各填充 6 字节。

### 第（2）问：S 已经收到的应用层数据字节数是多少？

#### 1. 考查知识点

- IPv4 总长度字段
- IPv4 首部长度
- TCP 首部长度
- TCP 数据长度计算
- TCP 序列号与确认号

#### 2. 解题思路

TCP 报文段的数据长度没有单独的长度字段，需要通过 IP 总长度减去 IP 首部长度和 TCP 首部长度得到：

\[
\boxed{TCP数据长度=IP总长度-IP首部长度-TCP首部长度}
\]

IPv4 首部第一个字节为 `45H`：

- 高 4 位 `4`：IPv4。
- 低 4 位 `5`：首部长度为 5 个 32 位字，即：

\[
5\times4=20\text{ 字节}
\]

TCP 首部长度由数据偏移字段表示。分组 4 的 TCP 首部第 13 个字节（从 TCP 首部起始处按偏移计数）为 `50H`，其高 4 位为 5，因此：

\[
TCP首部长度=5\times4=20\text{ 字节}
\]

#### 3. 计算分组 4 的应用层数据长度

分组 4 的 IP 总长度为：

\[
0038_H=56\text{ 字节}
\]

IP 首部长度：

\[
20\text{ 字节}
\]

TCP 首部长度：

\[
20\text{ 字节}
\]

因此 TCP 数据长度为：

\[
56-20-20=16\text{ 字节}
\]

分组 4 携带 16 字节 TCP 数据。题目所说的应用层数据，在本题中即这 16 字节 TCP 载荷。

#### 4. 用分组 5 的确认号验证

分组 4 的序列号为：

\[
Seq=846B41C6_H
\]

分组 5 的确认号为：

\[
Ack=846B41D6_H
\]

两者相减：

\[
846B41D6_H-846B41C6_H=10_H=16
\]

说明服务器确认已经按序收到从 `846B41C6H` 开始的 16 字节数据。

因此，S 已经收到的应用层数据字节数为：

\[
\boxed{16\text{ 字节}}
\]

#### 5. 第（2）问最终答案

\[
\boxed{16\text{ 字节}}
\]

### 第（3）问：该 IP 分组从 S 到达 H 时经过了多少个路由器？

#### 1. 考查知识点

- IPv4 标识字段
- IPv4 TTL（生存时间）
- 路由器转发时 TTL 的变化
- 十六进制与十进制转换

#### 2. 解题思路

题目给出：

- 题 47-b：某 IP 分组在 S 发出时的首部。
- 题 47-a：该分组到达 H 时捕获的首部。

需要先找到同一个 IP 分组，再比较两次的 TTL。

#### 3. 根据 IP 标识字段找到同一个分组

题 47-b 中：

```text
45 00 00 28 68 11 40 00 40 06 ...
```

其中 IP 标识字段为：

```text
68 11
```

即：

\[
ID=6811_H
\]

题 47-a 第 5 个分组的 IP 标识字段同样为：

```text
68 11
```

因此，题 47-b 对应题 47-a 中的第 5 个分组。

#### 4. 提取发送时和到达时的 TTL

IPv4 首部中，TTL 位于从首部起始位置偏移 8 字节处，即第 9 个字节。

**S 发出时（题 47-b）：**

```text
45 00 00 28 68 11 40 00 40 06 ...
                        ↑
                       TTL
```

TTL 为：

\[
40_H=64
\]

**H 捕获时（题 47-a 第 5 个分组）：**

```text
45 00 00 28 68 11 40 00 31 06 ...
                        ↑
                       TTL
```

TTL 为：

\[
31_H=49
\]

#### 5. 计算经过的路由器数量

IPv4 数据报每经过一个路由器，TTL 减 1。

因此：

\[
N=TTL_{\text{发送}}-TTL_{\text{接收}}
\]

代入：

\[
N=64-49=15
\]

所以，该 IP 分组从 S 到达 H 经过：

\[
\boxed{15\text{ 个路由器}}
\]

#### 6. 第（3）问最终答案

\[
\boxed{15\text{ 个路由器}}
\]

## 四、核心考点总结

### 1. IPv4 首部关键字段

| 字段 | 长度 | 作用 |
|---|---:|---|
| 版本 | 4 位 | 标识 IP 版本 |
| 首部长度 IHL | 4 位 | 表示 IP 首部长度，单位为 4 字节 |
| 总长度 | 16 位 | IP 首部与数据部分的总长度 |
| 标识 | 16 位 | 标识 IP 分组，常用于分片重组识别 |
| 标志、片偏移 | 16 位 | 分片控制与定位 |
| TTL | 8 位 | 限制 IP 分组生存时间 |
| 协议 | 8 位 | 指明上层协议，如 TCP=6 |
| 首部校验和 | 16 位 | 检查 IPv4 首部差错 |
| 源 IP 地址 | 32 位 | 发送方 IP 地址 |
| 目的 IP 地址 | 32 位 | 接收方 IP 地址 |

### 2. IPv4 首部长度计算

IHL 字段的单位是 4 字节：

\[
\boxed{IP首部长度=IHL\times4}
\]

例如：

- `45H`：IHL=5，首部长度 20 字节。
- `46H`：IHL=6，首部长度 24 字节。

### 3. TCP 首部长度计算

TCP 数据偏移字段的单位同样是 4 字节：

\[
\boxed{TCP首部长度=数据偏移\times4}
\]

TCP 首部最小 20 字节，最大 60 字节。

### 4. TCP 数据长度计算

\[
\boxed{TCP数据长度=IP总长度-IP首部长度-TCP首部长度}
\]

TCP 首部中没有专门表示数据长度的字段。

### 5. TCP 三次握手

| 次数 | 方向 | 标志位 | 关键作用 |
|---|---|---|---|
| 第一次 | 客户端→服务器 | SYN=1 | 请求建立连接 |
| 第二次 | 服务器→客户端 | SYN=1，ACK=1 | 确认客户端并发送自己的初始序列号 |
| 第三次 | 客户端→服务器 | ACK=1 | 确认服务器的初始序列号 |

SYN 和 FIN 各消耗一个序列号，纯 ACK 不消耗序列号。

### 6. 以太网最小帧长与填充

不带 VLAN 标签的传统以太网帧：

| 字段 | 长度 |
|---|---:|
| 目的 MAC 地址 | 6 字节 |
| 源 MAC 地址 | 6 字节 |
| 类型/长度字段 | 2 字节 |
| 数据字段 | 46～1500 字节 |
| FCS | 4 字节 |
| 最小帧长 | 64 字节 |

最小数据字段：

\[
64-6-6-2-4=46\text{ 字节}
\]

如果 IP 分组不足 46 字节，以太网在数据字段末尾填充：

\[
\boxed{填充长度=\max(0,46-IP分组长度)}
\]

填充字节不属于 IP 分组，不计入 IP 总长度。

### 7. TTL 与路由器数量

IPv4 数据报每经过一个路由器，TTL 减 1：

\[
\boxed{经过的路由器数量=发送时TTL-接收时TTL}
\]

注意 TTL 是由发送方设置的初始值，不一定固定为 64、128 或 255。

## 五、易错点

### 1. 不要把 IP 总长度和 TCP 数据长度混淆

IP 总长度包含：

\[
IP首部+TCP首部+TCP数据
\]

不能直接把 IP 总长度当成应用层数据长度。

### 2. TCP 首部长度不是固定 20 字节

TCP 首部最小 20 字节，存在选项时可以更长。

必须读取数据偏移字段，不能默认所有 TCP 首部都是 20 字节。

### 3. TCP 端口号可以辅助判断通信方向

本题中：

\[
0BD9_H=3033,\quad1388_H=5000
\]

源端口 3033、目的端口 5000 的报文是客户端 H 发往服务器 S；反方向则是服务器发往客户端。

但实际解析时还应结合 IP 地址、序列号、确认号和控制位综合判断。

### 4. SYN 和 FIN 会消耗序列号

- SYN 消耗 1 个序列号。
- FIN 消耗 1 个序列号。
- 纯 ACK 不消耗序列号。
- 数据部分每增加 1 字节，序列号增加 1。

### 5. 以太网填充不改变 IP 总长度

例如 IP 分组长度为 40 字节：

\[
46-40=6\text{ 字节}
\]

以太网增加 6 字节填充，但 IP 首部中的总长度仍然是 40 字节。

### 6. TTL 不是经过的链路数量

TTL 每经过一个路由器减 1。因此：

\[
TTL_{\text{发送}}-TTL_{\text{接收}}
\]

得到的是路由器数量，而不是链路数量。

### 7. IP 标识字段用于对应分组，但不能脱离其他字段机械判断

本题中题 47-b 与题 47-a 第 5 个分组的 ID 都是 `6811H`，并且总长度等其他信息也相符，因此可以对应起来。一般分析时应结合多个首部字段，尤其要考虑 NAT、分片和标识字段可能重复等情况。
