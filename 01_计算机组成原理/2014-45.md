# 2014-45 程序执行、Cache、异常与 TLB

> 本笔记依据题目给出的程序和机器指令整理。第三问的 TLB
> 查询次数按包含缺页后重新执行 `load` 指令的口径计算：至少 1001 次。

## 一、题目条件与程序

### 1. C 语言程序

``` c
for (int i = 0; i < N; i++)
    sum += A[i];
```

初始条件： - R1 = 0，保存 sum。 - R2 = 0，保存循环变量 i。 - R6 =
1000，保存 N。 - 程序代码已调入主存，但不在 Cache 中。 - 数组 A
尚未调入主存。 - 所有数组元素位于同一个页面，并存储在磁盘同一个扇区。

### 2. 机器指令

程序起始地址为 `08048100H`，每条指令 32 位，即 4 字节。

  编号   地址        汇编指令           功能
  ------ ----------- ------------------ ---------------------------------
  1      08048100H   `sll R4,R2,2`      R4 = R2 × 4，计算数组元素偏移量
  2      08048104H   `add R4,R4,R3`     R4 = R4 + R3，计算 A\[i\] 地址
  3      08048108H   `load R5,0(R4)`    从内存读取 A\[i\] 到 R5
  4      0804810CH   `add R1,R1,R5`     R1 = R1 + R5，累加数组元素
  5      08048110H   `add R2,R2,1`      R2 = R2 + 1，循环变量加 1
  6      08048114H   `bne R2,R6,loop`   若 R2 不等于 R6，则跳回 loop

寄存器作用：

  寄存器   作用
  -------- ------------------------------
  R1       sum，累加和
  R2       i，循环变量
  R3       数组 A 的首地址
  R4       计算数组元素地址的临时寄存器
  R5       当前读取的数组元素 A\[i\]
  R6       N，循环次数，值为 1000

## 二、第（1）问：程序结束时 R2 的内容

**答案：1000。**

每次循环执行第 5 条指令：

``` asm
add R2,R2,1
```

R2 每次增加 1。随后执行第 6 条指令：

``` asm
bne R2,R6,loop
```

-   R2 不等于 R6：跳回循环开始。
-   R2 等于 R6：不再跳转，程序结束。

执行过程：

    循环次数   第 5 条指令执行后 R2 判断          是否跳转
  ---------- ---------------------- ------------- ----------
           1                      1 1 != 1000     是
           2                      2 2 != 1000     是
         ...                    ... ...           ...
         999                    999 999 != 1000   是
        1000                   1000 1000 = 1000   否

因此程序结束时 R2 = 1000。

**易错点：不是 999。** 最后一次循环中，R2 先增加到
1000，然后才执行条件判断并退出。

## 三、第（2）问：指令 Cache 容量与命中率

题目条件： - 指令 Cache 有 16 行。 - Cache 与主存交换的块大小为 32
字节。 - 程序代码在主存中，但不在 Cache 中。

### 1. 指令 Cache 数据区容量

Cache 数据区容量 = Cache 行数 × 每行大小。

``` text
16 × 32B = 512B
```

**答案：512 字节。**

这里计算的是 Cache 数据区容量，不包括标记位、有效位等额外控制信息。

### 2. 程序总大小

程序共有 6 条指令，每条指令 4 字节：

``` text
6 × 4B = 24B
```

程序 P 的机器代码总大小为 24 字节。

### 3. 判断程序是否跨 Cache 块

Cache 块大小为 32 字节。程序起始地址为：

``` text
08048100H
```

该地址按 32 字节对齐，其所在块的地址范围为：

``` text
08048100H ～ 0804811FH
```

六条指令的地址从 `08048100H` 到 `08048114H`，全部位于同一个 32
字节块中。

因此，第一次访问指令 1 时 Cache 未命中，Cache 将整个 32
字节块调入；后续六条指令的访问均可命中。

### 4. 计算总指令访问次数

每次循环执行 6 条指令，共循环 1000 次：

``` text
总指令访问次数 = 6 × 1000 = 6000 次
```

### 5. 计算命中率

第一次取指未命中，后续访问均命中：

``` text
Cache 未命中次数 = 1 次
Cache 命中次数 = 6000 - 1 = 5999 次

命中率 = 5999 / 6000
       ≈ 99.9833%
```

**答案：指令 Cache 命中率约为 99.98%。**

**核心考点：Cache 按块调入，不是每次只调入一条指令。** 第一次访问指令 1
未命中后，整个 32 字节块进入 Cache，指令 2～6 也随之进入 Cache。

## 四、第（3）问：异常、磁盘访问与 TLB 查询

### 1. 哪条指令可能发生溢出异常？

**答案：第 4 条指令。**

``` asm
add R1,R1,R5
```

功能：

``` text
R1 = R1 + R5
```

对应 C 语言中的：

``` c
sum += A[i];
```

R1 保存累加和，R5 保存当前数组元素。若两个 32
位有符号整数相加后超出表示范围，就可能发生有符号溢出异常。

32 位有符号整数范围：

``` text
-2147483648 ～ 2147483647
```

例如：

``` text
R1 = 2147483640
R5 = 100
相加结果 = 2147483740
```

结果超过最大值，因此发生溢出异常。

  ------------------------------------------------------------------------------------
  指令                    是否可能发生溢出        原因
  ----------------------- ----------------------- ------------------------------------
  1：`sll R4,R2,2`        否                      R2 最大为 999，左移 2 位后最大为
                                                  3996

  2：`add R4,R4,R3`       正常情况下不考虑        计算有效数组地址，题目默认地址有效

  3：`load R5,0(R4)`      不属于溢出异常          可能发生缺页异常

  4：`add R1,R1,R5`       **是**                  累加结果可能超出有符号整数范围

  5：`add R2,R2,1`        否                      R2 只从 0 增加到 1000

  6：`bne R2,R6,loop`     否                      条件分支指令，不进行加法运算
  ------------------------------------------------------------------------------------

### 2. 哪条指令可能产生缺页异常？

**答案：第 3 条指令。**

``` asm
load R5,0(R4)
```

功能是从内存中读取数组元素 A\[i\]。

题目明确指出数组 A 尚未调入主存，因此第一次执行 `load` 时： 1. CPU
产生数组元素的虚拟地址。 2. 查询 TLB，未找到对应的地址映射。 3.
查询页表，发现数组 A 所在页面不在主存。 4. 产生缺页异常。 5.
操作系统将对应页面从磁盘调入主存。 6. 更新页表和相应的地址转换信息。 7.
返回后重新执行发生缺页的 `load` 指令。

因此，可能发生缺页异常的是第 3 条 `load` 指令。

### 3. 访问数组 A，需要读磁盘多少次？

**答案：至少 1 次。**

题目给出： - 所有数组元素都位于同一个页面； -
所有数组元素存储在磁盘同一个扇区。

第一次执行 `load A[0]`
时，数组所在页面不在主存，因此产生缺页异常，需要从磁盘读取相应数据并调入页面。

页面调入后，A\[1\]、A\[2\]......A\[999\]
仍然位于同一个页面，不需要再次调入该页面。

``` text
磁盘读取次数 = 1 次
```

**关键：虚拟存储器以页为单位调页，不是每访问一个数组元素就从磁盘读取一次。**

### 4. 访问数组 A，需要查询 TLB 多少次？

**答案：至少 1001 次。**

先区分三个概念： - TLB 查询：每次需要进行地址转换时查询 TLB。 - TLB
未命中：查询 TLB 后没有找到对应映射。 -
缺页异常：页表表明所需虚拟页面不在主存。

#### 第一步：正常情况下有 1000 次数组访问

程序循环执行 1000 次，每次都执行：

``` asm
load R5,0(R4)
```

所以正常的数组元素读取次数为 1000
次。每次访问数组元素都需要进行虚拟地址转换，因此每次都需要查询 TLB。

#### 第二步：第一次访问 A\[0\] 时发生缺页

第一次执行 `load`： 1. 查询 TLB； 2. TLB 未命中； 3. 查询页表； 4.
发现页面不在主存； 5. 产生缺页异常； 6. 操作系统从磁盘调入页面。

这次查询虽然未命中，但仍然算一次 TLB 查询。

#### 第三步：缺页处理完成后重新执行 load

缺页处理完成后，CPU 需要重新执行刚才因缺页而中断的 `load` 指令。

重新执行时，还需要再次查询 TLB。此时地址映射已经建立，通常可以命中。

因此，第一次访问 A\[0\] 实际涉及两次 TLB 查询： - 第一次：TLB
未命中，随后发现缺页； - 第二次：缺页处理完成，重新执行 `load`，再次查询
TLB。

#### 第四步：访问剩余 999 个数组元素

A\[1\]～A\[999\]
都位于同一个页面。页面已经调入主存，地址映射也已建立，因此后续 999
次访问通常都能命中 TLB。

#### 第五步：精确计算

  访问过程                           TLB 查询次数 说明
  -------------------------------- -------------- --------------------------
  第一次执行 `load A[0]`                        1 TLB 未命中，随后发生缺页
  缺页处理后重新执行 `load A[0]`                1 再次查询 TLB，通常命中
  读取 A\[1\]～A\[999\]                       999 同一页面，通常命中
  **合计**                               **1001** 

``` text
TLB 查询次数
= 1 + 1 + 999
= 1001 次
```

**因此，按照包含缺页后重新执行 `load` 指令的精确统计口径，访问数组 A
至少需要查询 TLB 1001 次。**

注意：这里仅统计对数组 A
的地址转换查询，不包括取指过程和操作系统缺页处理程序自身可能产生的其他地址转换访问。

## 五、Cache、TLB 与缺页异常的区别

  -----------------------------------------------------------------------------
  项目                  含义                                           本题数量
  --------------------- -------------------------- ----------------------------
  Cache 未命中          所需指令或数据不在 Cache    指令 Cache 首次取指未命中 1
                        中                                                   次

  TLB 未命中            所需地址映射不在 TLB 中         初次访问数组时至少 1 次

  缺页异常              所需虚拟页面不在主存中                             1 次

  磁盘读取              将所需页面从磁盘调入主存                      至少 1 次

  TLB 查询              每次进行地址转换时查询 TLB                 至少 1001 次
  -----------------------------------------------------------------------------

### 高频易错点

1.  Cache 未命中不等于缺页异常。Cache
    未命中通常从下一层存储器获取数据；缺页异常需要操作系统处理。
2.  TLB 未命中不一定发生缺页异常。页表中可能存在映射，只是 TLB
    没有缓存该映射。
3.  TLB 命中也算一次 TLB 查询。查询次数不能只统计未命中次数。
4.  同一个页面只需要调入一次，但页面中的不同元素每次访问仍然需要进行地址转换。
5.  缺页处理完成后，原来引发缺页的指令需要重新执行，因此精确统计时要考虑重新执行带来的额外查询。

## 七、408 考前记忆

### 1. Cache

-   Cache 按块调入。
-   第一次访问某个块可能未命中，调入后同块数据可以命中。
-   命中率 = 命中次数 / 总访问次数。

### 2. 虚拟存储器

-   虚拟存储器按页管理。
-   页面不在主存时发生缺页异常。
-   缺页处理完成后，需要重新执行引发缺页的指令。

### 3. TLB

-   TLB 缓存页表项，加速地址转换。
-   每次需要进行虚拟地址转换时，都要查询 TLB。
-   TLB 命中也算一次查询。
-   统计查询次数时，注意缺页后重新执行指令带来的额外查询。

### 4. 异常

-   有符号加法结果超出表示范围，可能发生溢出异常。
-   访问不在主存中的虚拟页面，可能发生缺页异常。
-   不同异常由不同的指令和条件触发。

**本题最重要的记忆：1000 次数组元素读取，加上第一次缺页处理后重新执行
`load` 的 1 次查询，合计至少 1001 次 TLB 查询。**
