# 2011-44 地址位划分、Cache命中与TLB判断

## 一、基本信息

- **一级主要考点：** 存储器层次结构
- **二级考点：** 虚拟存储器、页表、TLB、Cache地址划分、直接映射Cache
- **题目分值：** 12分
- **题目类型：** 综合计算与地址转换题

## 二、题目条件整理

| 参数 | 已知条件 |
|---|---|
| 虚拟地址空间 | 16MB |
| 主存地址空间 | 1MB |
| 页面大小 | 4KB |
| Cache映射方式 | 直接映射 |
| Cache行数 | 8行 |
| 主存与Cache交换块大小 | 32B |
| TLB结构 | 4路组相联 |
| TLB容量 | 8个页表项 |

注意：本题按字节编址。

## 三、逐问解析

### 第（1）问：虚拟地址和物理地址的位数

**① 虚拟地址位数**

虚拟地址空间为16MB：

16MB = 16 × 2²⁰ = 2²⁴B

因此，虚拟地址共24位。

页面大小为4KB：

4KB = 2¹²B

因此，页内偏移量占12位。

虚页号位数：

24 - 12 = 12位

虚拟地址划分：

| 字段 | 位数 | 地址位 |
|---|---:|---|
| 虚页号VPN | 12位 | 23～12 |
| 页内偏移量 | 12位 | 11～0 |

**② 物理地址位数**

主存地址空间为1MB：

1MB = 2²⁰B

因此，物理地址共20位。

页面大小为4KB，即2¹²B。

页框号位数：

20 - 12 = 8位

物理地址划分：

| 字段 | 位数 | 地址位 |
|---|---:|---|
| 页框号PFN | 8位 | 19～12 |
| 页内偏移量 | 12位 | 11～0 |

**本问答案：**

- 虚拟地址：24位，其中虚页号12位，页内偏移量12位。
- 物理地址：20位，其中页框号8位，页内偏移量12位。

### 第（2）问：使用物理地址访问Cache时，地址如何划分？

已知：

- 主存地址20位。
- Cache采用直接映射。
- Cache共有8行。
- 每行大小32B。

物理地址划分为：

**① 块内地址（块内偏移）**

每行32B：

32 = 2⁵

因此，块内地址占5位。

**② Cache行号**

Cache共有8行：

8 = 2³

因此，Cache行号占3位。

**③ 标记（Tag）**

剩余位数：

20 - 5 - 3 = 12位。

**最终地址划分：**

| 字段 | 位数 | 物理地址位置 |
|---|---:|---|
| 标记Tag | 12位 | 19～8 |
| Cache行号 | 3位 | 7～5 |
| 块内地址 | 5位 | 4～0 |

**本问答案：**

物理地址划分为12位标记、3位Cache行号、5位块内地址。

### 第（3）问：虚拟地址001C60H所在页面是否在主存？访问Cache是否命中？

**第一步：将虚拟地址拆分为虚页号和页内偏移量。**

虚拟地址：

001C60H

由于页大小为4KB，即1000H，因此：

- 虚页号VPN = 001H
- 页内偏移量 = C60H

**第二步：查页表，判断页面是否在主存。**

根据题目给出的页表：

虚页号1对应的页表项：

- 有效位 = 1
- 页框号 = 04H

有效位为1，说明该页面在主存中。

因此，虚页号001H映射到物理页框04H。

**第三步：计算物理地址。**

物理地址 = 页框号 × 页面大小 + 页内偏移量

= 04H × 1000H + C60H

= 04C60H

**第四步：划分物理地址，查找Cache。**

物理地址：

04C60H

根据第（2）问：

- Tag占12位。
- Cache行号占3位。
- 块内地址占5位。

计算：

Cache行号：

(04C60H >> 5) mod 8 = 3

标记：

04C60H >> 8 = 04CH

块内地址：

04C60H & 1FH = 00H

因此：

- Cache行号 = 3
- Tag = 04CH
- 块内地址 = 00H

**第五步：查Cache表。**

根据题目给出的Cache表：

Cache第3行：

- 有效位 = 1
- 标记 = 105H

比较：

| 项目 | 计算结果 | Cache第3行 |
|---|---|---|
| 有效位 | 1 | 1 |
| 标记 | 04CH | 105H |

虽然有效位均为1，但是标记不相等。

因此，Cache不命中。

**本问答案：**

- 页面在主存中。
- 对应物理地址为04C60H。
- Cache访问不命中。

### 第（4）问：根据TLB判断虚拟地址024BACH所在页面是否在主存？

已知：

- TLB采用4路组相联。
- TLB共存放8个页表项。

**第一步：计算TLB组数。**

组数 = TLB总项数 ÷ 路数

= 8 ÷ 4

= 2组

因此，TLB有2组，每组4个表项。

组号占：

log₂2 = 1位。

**第二步：拆分虚拟地址。**

虚拟地址：

024BACH

页大小为4KB，即1000H。

因此：

- 虚页号VPN = 024H
- 页内偏移量 = BACH

**第三步：计算TLB组号和标记。**

TLB组号取虚页号的低1位。

024H转换为二进制：

0000 0010 0100

最低位为0。

因此：

TLB组号 = 0

TLB标记 = VPN右移1位

= 024H >> 1

= 012H

**第四步：查找TLB第0组。**

根据题目给出的TLB表，第0组中：

| 有效位 | 标记 | 页框号 |
|---|---|---|
| 0 | — | — |
| 0 | — | — |
| 1 | 001H | 15H |
| 1 | 012H | 1FH |

查找结果：

- 组号 = 0
- 标记 = 012H
- 对应表项有效位 = 1
- 对应页框号 = 1FH

标记匹配且有效位为1，说明TLB命中。

TLB命中意味着已经获得有效的页框号，该页面在主存中。

**本问答案：**

虚拟地址024BACH所在页面在主存中。

其对应页框号为1FH。

如果进一步计算物理地址：

物理地址 = 1FH × 1000H + BACH

= 1FBACH

## 四、核心考点总结

### 1. 地址位数计算

- 地址空间为2ⁿB，地址位数为n。
- 页内偏移位数 = log₂页面大小。
- 虚页号位数 = 虚拟地址位数 - 页内偏移位数。
- 页框号位数 = 物理地址位数 - 页内偏移位数。

### 2. Cache地址划分

直接映射Cache：

| 字段 | 计算公式 |
|---|---|
| 块内地址 | log₂块大小 |
| Cache行号 | log₂Cache行数 |
| Tag | 物理地址位数 - 块内地址位数 - 行号位数 |

Cache命中条件：

1. 对应Cache行有效位为1。
2. Cache中的Tag与访问地址的Tag相等。

两个条件必须同时满足。

### 3. TLB地址划分

组相联TLB：

- 组数 = TLB总项数 ÷ 路数。
- 组号位数 = log₂组数。
- TLB标记 = 虚页号中除组号以外的剩余位。

TLB命中条件：

1. 组号匹配。
2. 标记匹配。
3. 有效位为1。

### 4. 虚拟地址转换流程

TLB命中：

虚拟地址 → TLB → 页框号 → 物理地址

TLB不命中：

虚拟地址 → 查页表 → 判断页表有效位 → 获取页框号 → 物理地址

如果页表项无效，则产生缺页异常。

## 五、易错点

1. 虚拟地址转换时，页内偏移量不发生变化。
2. 页表存储虚页号与物理页框号的映射关系。
3. Cache使用物理地址访问时，必须先完成地址转换。
4. Cache命中不能只看有效位，还要比较标记。
5. TLB的组号来自虚页号，而不是页内偏移量。
6. TLB命中表示找到了有效的地址映射，不需要再查页表。
7. TLB有效位与页表有效位含义不能混淆。
