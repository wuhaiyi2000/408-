# 2014-44（12分）：存储器编址、数组寻址、分支指令与流水线冒险

## 一、题目

某程序中有如下循环代码段 P：

```c
for (int i = 0; i < N; i++)
    sum += A[i];
```

假设编译时变量 sum 和 i 分别分配在寄存器 R1 和 R2 中。常量 N 在寄存器 R6 中，数组 A 的首地址在寄存器 R3 中。

程序段 P 起始地址为 `08048100H`，对应的汇编代码和机器代码如下：

| 编号 | 地址 | 机器代码 | 汇编代码 | 功能 |
|---|---|---|---|---|
| 1 | 08048100H | 00022080H | `loop: sll R4, R2, 2` | (R2) 左移2位 -> R4 |
| 2 | 08048104H | 00083020H | `add R4, R4, R3` | (R4) + (R3) -> R4 |
| 3 | 08048108H | 8C850000H | `load R5, 0(R4)` | ((R4)+0) -> R5 |
| 4 | 0804810CH | 00250820H | `add R1, R1, R5` | (R1) + (R5) -> R1 |
| 5 | 08048110H | 20420001H | `add R2, R2, 1` | (R2) + 1 -> R2 |
| 6 | 08048114H | 1446FFFAH | `bne R2, R6, loop` | 若 R2 != R6，则跳转到 loop |

执行上述代码的计算机 M 采用32位定长指令字，其中分支指令 bne 采用以下格式：

| 字段 | 位数 |
|---|---|
| OP | 31～26，共6位 |
| Rs | 25～21，共5位 |
| Rd | 20～16，共5位 |
| OFFSET | 15～0，共16位 |

OP 为操作码，Rs 和 Rd 为寄存器编号，OFFSET 为偏移量，用补码表示。

请回答下列问题，并说明理由。

（1）M的存储器编址单位是什么？

（2）已知 sll 指令实现左移功能，数组 A 中每个元素占多少位？

（3）题目表中 bne 指令的 OFFSET 字段的值是多少？已知 bne 指令采用相对寻址方式，当前 PC 内容为 bne 指令地址，通过分析指令地址和 bne 指令内容，推断 bne 指令的转移目标地址计算公式。

（4）若 M 采用如下按序发射、按序完成的5级指令流水线：

- IF：取指
- ID：译码及取数
- EXE：执行
- MEM：访存
- WB：写回寄存器

且硬件不采取任何转发措施，分支指令的执行均引起3个时钟周期阻塞，则 P 中哪些指令的执行会由于数据相关而发生流水线阻塞？哪些指令的执行会发生控制冒险？为什么指令1的执行不会因为与指令5的数据相关而发生阻塞？

## 二、第（1）问：判断存储器编址单位

### 1. 观察指令地址

程序中各条指令的地址如下：

| 指令 | 地址 |
|---|---|
| 指令1 | 08048100H |
| 指令2 | 08048104H |
| 指令3 | 08048108H |
| 指令4 | 0804810CH |
| 指令5 | 08048110H |
| 指令6 | 08048114H |

相邻两条指令的地址相差：

`08048104H - 08048100H = 4`

### 2. 分析

题目告诉我们：

- 计算机采用32位定长指令。
- 32位 = 4字节。
- 每条指令占用4字节。

相邻指令地址恰好相差4，说明地址每增加1，表示增加1字节。

因此，M采用的是**按字节编址**。

### 最终答案

`存储器编址单位 = 1B（字节）`

## 三、第（2）问：计算数组每个元素占多少位

### 1. 分析 sll 指令

指令1：

```asm
sll R4, R2, 2
```

sll 是逻辑左移指令。

功能：

`R4 = R2 << 2`

左移2位相当于乘以4：

`R4 = R2 × 4`

其中：

- R2 保存数组下标 i。
- R3 保存数组 A 的首地址。

### 2. 分析数组地址计算

指令2：

```asm
add R4, R4, R3
```

功能：

`R4 = R4 + R3`

将两条指令结合：

`R4 = R3 + R2 × 4`

而数组元素的地址计算公式是：

`A[i]的地址 = 数组首地址 + i × 每个元素占用的字节数`

对比可知：

`每个数组元素占用 4B`

换算为位：

`4B × 8 = 32位`

### 最终答案

`数组A中每个元素占32位，即4字节。`

## 四、第（3）问：计算 bne 指令的 OFFSET 和转移目标地址

### 1. 提取 OFFSET 字段

bne 指令的机器代码：

`1446FFFAH`

题目规定：

| 字段 | 位数 |
|---|---|
| OP | 6位 |
| Rs | 5位 |
| Rd | 5位 |
| OFFSET | 16位 |

因此，OFFSET 是机器代码的低16位。

`OFFSET = FFFAH`

### 2. 将 OFFSET 转换为有符号十进制数

题目规定 OFFSET 使用补码表示。

`FFFAH` 是一个16位补码。

最高位为1，说明它表示负数。

求其绝对值：

第一步：按位取反。

`FFFAH -> 0005H`

第二步：加1。

`0005H + 1 = 0006H`

所以：

`OFFSET = -6`

### 3. 推导转移目标地址公式

已知：

- bne 指令采用相对寻址。
- 当前 PC 内容为 bne 指令地址。
- bne 指令地址为 08048114H。
- OFFSET = -6。

先看程序中的指令地址：

| 指令 | 地址 |
|---|---|
| 指令1（loop） | 08048100H |
| 指令6（bne） | 08048114H |

bne 指令的下一条指令地址：

`PC + 4 = 08048118H`

从下一条指令地址跳转到 loop：

`08048100H - 08048118H = -18H`

转换为十进制：

`-18H = -24`

而 OFFSET = -6。

可以发现：

`-24 / -6 = 4`

也就是说，OFFSET 的一个单位代表4字节，也就是一条指令的长度。

因此，转移目标地址计算公式为：

`目标地址 = (PC + 4) + OFFSET × 4`

### 4. 验证

代入：

`目标地址 = 08048118H + (-6) × 4`

`= 08048118H - 18H`

`= 08048100H`

恰好等于 loop 的地址。

### 最终答案

- OFFSET 字段：`FFFAH`
- OFFSET 的有符号十进制值：`-6`
- 转移目标地址：`08048100H`

目标地址计算公式：

`目标地址 = (PC + 4) + sign_extend(OFFSET) × 4`

其中 sign_extend 表示符号扩展。

## 五、第（4）问：五级流水线的数据冒险与控制冒险

这是本题最重要的考点。

### 1. 首先梳理五级流水线

| 阶段 | 名称 | 功能 |
|---|---|---|
| IF | 取指 | 从指令存储器取出指令 |
| ID | 译码及取数 | 解析指令，读取源寄存器 |
| EXE | 执行 | ALU进行运算或计算有效地址 |
| MEM | 访存 | 访问数据存储器 |
| WB | 写回 | 将结果写入寄存器 |

题目明确说明：

- 不采用数据转发。
- 按序发射、按序完成。
- 分支指令执行均引起3个时钟周期阻塞。

**关键：没有转发意味着，后续指令不能提前从前一条指令的流水线中直接取得结果，必须等待结果写回寄存器。**

### 2. 梳理每条指令读取和写入的寄存器

| 指令 | 汇编代码 | 读取的寄存器 | 写入的寄存器 |
|---|---|---|---|
| I1 | sll R4, R2, 2 | R2 | R4 |
| I2 | add R4, R4, R3 | R4、R3 | R4 |
| I3 | load R5, 0(R4) | R4 | R5 |
| I4 | add R1, R1, R5 | R1、R5 | R1 |
| I5 | add R2, R2, 1 | R2 | R2 |
| I6 | bne R2, R6, loop | R2、R6 | PC（满足条件时改变） |

### 3. 找出数据相关

数据冒险主要关注 RAW（写后读）相关：

即前一条指令要写入某个寄存器，后一条指令需要读取这个寄存器。

本题存在以下依赖：

#### （1）I1 -> I2：R4相关

I1：

```asm
sll R4, R2, 2
```

计算结果写入 R4。

I2：

```asm
add R4, R4, R3
```

需要读取 R4。

因此：

`I1写R4 -> I2读R4`

属于 RAW 数据相关。

由于没有转发，I2必须等待I1将结果写回R4后才能读取。

**I2发生数据相关阻塞。**

#### （2）I2 -> I3：R4相关

I2：

```asm
add R4, R4, R3
```

计算数组元素的有效地址，写入R4。

I3：

```asm
load R5, 0(R4)
```

需要读取R4作为访存地址。

因此：

`I2写R4 -> I3读R4`

属于 RAW 数据相关。

I3必须等待I2写回R4。

**I3发生数据相关阻塞。**

#### （3）I3 -> I4：R5相关

I3：

```asm
load R5, 0(R4)
```

从内存中取出数组元素，写入R5。

I4：

```asm
add R1, R1, R5
```

需要读取R5，将数组元素累加到sum中。

因此：

`I3写R5 -> I4读R5`

属于 RAW 数据相关。

I4必须等待I3将数据写回R5。

**I4发生数据相关阻塞。**

#### （4）I5 -> I6：R2相关

I5：

```asm
add R2, R2, 1
```

将数组下标加1，结果写入R2。

I6：

```asm
bne R2, R6, loop
```

需要读取R2，与R6比较。

因此：

`I5写R2 -> I6读R2`

属于 RAW 数据相关。

I6必须等待I5写回R2。

**I6发生数据相关阻塞。**

### 4. 数据冒险总结

| 数据生产者 | 数据消费者 | 相关寄存器 | 是否发生数据阻塞 |
|---|---|---|---|
| I1 | I2 | R4 | 是 |
| I2 | I3 | R4 | 是 |
| I3 | I4 | R5 | 是 |
| I5 | I6 | R2 | 是 |

因此：

**发生数据相关阻塞的指令是：I2、I3、I4、I6。**

注意：这里判断的是哪些指令存在需要等待的 RAW 数据相关，不代表每条指令都固定阻塞相同的时钟周期。

### 5. 控制冒险

控制冒险是由于分支、跳转等指令改变程序执行顺序，导致CPU无法确定下一条应该取哪条指令。

本题中的分支指令：

```asm
bne R2, R6, loop
```

功能：

`如果R2 != R6，则跳转到loop。`

如果条件成立：

`PC = 08048100H`

如果条件不成立：

`PC = 08048118H`

CPU在确定分支结果之前，无法确定下一条应该取哪条指令。

因此：

- I6是分支指令。
- I6执行时会产生控制冒险。
- 题目规定每条分支指令引起3个时钟周期阻塞。

**控制冒险由I6（bne）引起，每次分支产生3个时钟周期的阻塞。**

注意：数据冒险和控制冒险是两种不同的阻塞原因。I6既存在R2的数据相关，也存在分支控制冒险。

### 6. 为什么I1不会因为与I5的数据相关而发生阻塞？

这是本题特别容易混淆的地方。

I1：

```asm
sll R4, R2, 2
```

读取R2。

I5：

```asm
add R2, R2, 1
```

写入R2。

乍看之下，两条指令都使用R2，似乎存在数据相关。

实际上要分两种情况。

#### 情况一：同一轮循环

I1先执行，读取R2中的数组下标。

I5在后面执行，才将R2加1。

也就是说：

- I1先读取R2。
- I5后写入R2。

这是 WAR（写后读）相关，也叫反相关。

由于流水线按序发射，I1在ID阶段读取R2，而I5要到WB阶段才写入R2。

所以I1读取旧值时，I5还没有修改R2。

**同一轮循环中，I1不会因为I5而发生数据阻塞。**

#### 情况二：相邻两轮循环

上一轮循环的I5：

```asm
add R2, R2, 1
```

会更新R2。

下一轮循环的I1：

```asm
sll R4, R2, 2
```

需要读取更新后的R2。

这里确实存在跨循环的 RAW 数据相关：

`上一轮I5写R2 -> 下一轮I1读R2`

但是，上一轮循环的I6是分支指令：

```asm
bne R2, R6, loop
```

题目规定每次分支会造成3个时钟周期阻塞。

这些阻塞使下一轮I1有足够的时间等待上一轮I5完成R2的写回。

因此：

**虽然相邻两轮循环之间存在RAW相关，但由于分支指令造成的3个时钟周期阻塞，下一轮I1执行时R2已经写回，不需要额外的数据相关阻塞。**

### 7. 第（4）问最终答案

- 数据相关阻塞：I2、I3、I4、I6。
- 控制冒险：I6（bne）。
- I1与同一轮I5之间属于WAR反相关，按序流水线下不会产生数据阻塞。
- I1与上一轮I5之间存在跨循环RAW相关，但I6引起的3个时钟周期阻塞使该相关得到解决。

## 七、本题考点速记

1. **指令地址判断编址方式：** 32位指令占4B，相邻指令地址相差4，说明按字节编址。
2. **数组寻址：** 左移2位相当于乘以4，说明数组元素占4B，即32位。
3. **MIPS分支寻址：** 目标地址 = PC + 4 + 符号扩展后的OFFSET × 4。
4. **RAW数据冒险：** 前一条指令写寄存器，后一条指令读取该寄存器。
5. **无转发流水线：** 依赖指令需要等待生产者写回寄存器。
6. **控制冒险：** 分支指令改变下一条指令的执行地址。
7. **循环相关：** 注意区分同一轮循环的WAR反相关与相邻循环之间的RAW相关。

**本题最重要的两个判断：无转发时，RAW相关需要等待写回；循环中的分支阻塞可能消除跨循环的数据冒险。**
