# 2013-43 Cache缺失、8体交叉存储与总线带宽计算

## 一、题目

某32位计算机，CPU主频为800MHz，Cache命中时的CPI为4，Cache块大小为32字节；主存采用8体交叉存储方式，每个体的存储字长为32位、存储周期是40ns；存储器总线宽度为32位，总线时钟频率为200MHz，支持突发传送总线事务。

每次读突发传送总线事务的过程包括：送地址和命令、存储器准备数据、传送数据。每次突发传送32字节，传送地址或者32位数据均需要一个总线时钟周期。

请回答下列问题，要求给出理由或计算过程。

（1）CPU和总线的时钟周期各是多少？总线的带宽（即最大数据传输率）为多少？

（2）Cache缺失时，需要用几个读突发传送总线事务来完成一个主存块的读取？

（3）存储器总线完成一次读突发传送总线事务所需的时间是多少？

（4）若程序BP执行过程中，共执行了100条指令，平均每条指令需要1.2次访存，Cache缺失率是5%，不考虑替换等开销，则BP的CPU执行时间是多少？

## 三、第（1）问：计算CPU和总线时钟周期、总线带宽

### 1. CPU时钟周期

公式：

`CPU时钟周期 = 1 / CPU主频`

代入：

`T_CPU = 1 / (800 × 10^6)`

结果：

`T_CPU = 1.25ns`

### 2. 总线时钟周期

公式：

`总线时钟周期 = 1 / 总线时钟频率`

代入：

`T_bus = 1 / (200 × 10^6)`

结果：

`T_bus = 5ns`

### 3. 总线最大带宽

总线宽度为32位，即每次最多传输4B。

每个总线时钟周期可以传输4B。

公式：

`总线带宽 = 总线宽度 / 总线时钟周期`

代入：

`BW = 4B / 5ns`

`BW = 800MB/s`

**第（1）问答案：**

- CPU时钟周期：1.25ns
- 总线时钟周期：5ns
- 总线最大带宽：800MB/s

## 四、第（2）问：Cache缺失需要几个读突发传送事务？

已知：

- Cache块大小为32B。
- 每次突发传送32B。

因此：

`突发传送次数 = Cache块大小 / 每次突发传送大小`

`N = 32B / 32B = 1`

**答案：需要1个读突发传送总线事务。**

注意：

一个Cache块虽然是32B，但每个存储体字长只有32位，即4B。

所以一个Cache块包含：

`32B / 4B = 8个存储字`

这8个存储字通过一次突发传送事务完成传输。

## 五、第（3）问：计算一次读突发传送总线事务的时间

### 1. 分析题目给出的三个阶段

题目明确规定，一次读突发传送包括：

1. 发送地址和命令。
2. 存储器准备数据。
3. 传送数据。

注意：存储器准备数据与总线传输数据可以流水式重叠，不能简单地将两个阶段的全部时间直接相加。

### 2. 第一阶段：发送地址和命令

题目告诉我们，传送地址需要一个总线时钟周期。

`T1 = 5ns`

### 3. 第二阶段：存储器准备数据

首先计算一个Cache块包含多少个存储字。

Cache块大小为32B，每个存储体字长为32位，即4B。

`存储字数量 = 32B / 4B = 8`

因此需要读取8个存储字。

由于采用8体交叉存储，8个存储体可以错开启动。

相邻存储体的启动间隔为：

`启动间隔 = 存储周期 / 存储体数量`

`= 40ns / 8`

`= 5ns`

注意区分：

- 存储周期40ns：一个存储体完成一次访问所需的时间。
- 启动间隔5ns：相邻存储体开始工作的时间间隔。
- 第一个字仍然需要完整的40ns才能准备好。

8个存储体的工作过程：

| 存储体 | 开始准备 | 准备完成 |
|---|---:|---:|
| M1 | 0ns | 40ns |
| M2 | 5ns | 45ns |
| M3 | 10ns | 50ns |
| M4 | 15ns | 55ns |
| M5 | 20ns | 60ns |
| M6 | 25ns | 65ns |
| M7 | 30ns | 70ns |
| M8 | 35ns | 75ns |

因此，8个存储字全部准备完成所需时间：

`T2 = 40 + 7 × 5`

`T2 = 75ns`

注意：不是8 × 40ns，也不是8 × 5ns。

### 4. 第三阶段：传输数据

一个Cache块包含8个存储字。

总线宽度为32位，即每次传输4B。

每传输一个32位数据，需要一个总线时钟周期，即5ns。

因此，传输全部8个字需要：

`T3 = 8 × 5 = 40ns`

但是，这里不能直接将75ns和40ns相加。

**原因：存储器准备后续数据的过程，与总线传输前面已经准备好的数据可以重叠。**

具体过程：

| 存储体 | 数据准备时间 | 总线传输时间 |
|---|---|---|
| M1 | 0～40ns | 40～45ns |
| M2 | 5～45ns | 45～50ns |
| M3 | 10～50ns | 50～55ns |
| M4 | 15～55ns | 55～60ns |
| M5 | 20～60ns | 60～65ns |
| M6 | 25～65ns | 65～70ns |
| M7 | 30～70ns | 70～75ns |
| M8 | 35～75ns | 75～80ns |

可以看到：

- M1在40ns准备好，立即开始传输。
- M2在45ns准备好，紧接着传输。
- M3在50ns准备好，紧接着传输。
- 后续数据依次衔接。
- M8在75ns准备好，75～80ns完成传输。

因此，从第一个存储体开始准备，到最后一个数据传输完成，实际需要：

`T2+T3 = 75 + 5 = 80ns`

也可以理解为：

存储器准备数据和总线传输数据存在35ns的重叠。

`实际时间 = 75 + 40 - 35 = 80ns`

### 5. 计算总时间

加上第一阶段发送地址和命令的时间：

`总时间 = 地址和命令时间 + 准备与传输的重叠时间`

`T = 5 + 80`

`T = 85ns`

**第（3）问答案：一次读突发传送总线事务需要85ns。**

## 六、第（4）问：计算程序BP的CPU执行时间

已知：

- 指令总数：100条。
- 平均每条指令访存：1.2次。
- Cache缺失率：5%。
- Cache命中时CPI：4。
- CPU时钟周期：1.25ns。
- 一次Cache缺失需要85ns。

核心思路：

`CPU总执行时间 = 正常执行时间 + Cache缺失造成的额外等待时间`

### 1. 计算正常执行时间

Cache命中时CPI为4。

100条指令正常执行所需时钟周期：

`正常执行周期数 = 100 × 4 = 400`

转换为实际时间：

`T_normal = 400 × 1.25ns`

`T_normal = 500ns`

### 2. 计算总访存次数

平均每条指令需要1.2次访存。

`总访存次数 = 100 × 1.2`

`= 120次`

### 3. 计算Cache缺失次数

Cache缺失率为5%。

`Cache缺失次数 = 120 × 5%`

`= 6次`

### 4. 计算Cache缺失造成的额外等待时间

第（3）问已经计算出：

一次Cache缺失需要85ns。

因此，6次Cache缺失造成的额外等待时间：

`T_stall = 6 × 85ns`

`T_stall = 510ns`

也可以将一次缺失时间转换为CPU时钟周期：

`每次缺失等待周期数 = 85 / 1.25 = 68`

6次缺失：

`额外等待周期数 = 6 × 68 = 408`

### 5. 计算CPU总执行时间

正常执行时间为500ns，Cache缺失额外等待时间为510ns。

`T_total = 500 + 510`

`T_total = 1010ns`

换算：

`1010ns = 1.01μs`

**第（4）问答案：程序BP的CPU执行时间为1.01μs。**

## 八、易错点总结

### 1. CPU周期和总线周期

- CPU周期由CPU主频决定。
- 总线周期由总线时钟频率决定。
- 计算总线带宽时，使用总线宽度和总线周期。

### 2. 存储周期和交叉启动间隔

- 存储周期40ns：单个存储体完成一次访问的时间。
- 启动间隔5ns：相邻存储体启动工作的时间间隔。
- 第一个字需要等待40ns，后续字每隔5ns准备好一个。

### 3. 存储器准备数据和传输数据

这是本题最重要的易错点。

存储器准备后续数据的过程，可以与总线传输前面已经准备好的数据重叠。

因此：

- 准备8个字：75ns。
- 传输8个字：40ns。
- 两个阶段不能直接相加。
- 准备与传输合计：80ns。
- 加上地址和命令：85ns。

### 4. Cache缺失损失时间

Cache命中时CPI是正常执行的基础。

Cache缺失造成的等待时间需要额外计算。

计算公式：

`CPU总执行时间 = 指令总数 × 命中时CPI × CPU时钟周期 + Cache缺失次数 × 单次缺失时间`

其中：

`Cache缺失次数 = 指令总数 × 平均每条指令访存次数 × Cache缺失率`

**本题最终结果：1.01μs。**
