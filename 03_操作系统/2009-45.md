# 2009-45 进程缓冲区（生产者-消费者）

## 一、基本信息

-   **一级主要考点：** 操作系统------进程与线程
-   **二级考点：**
    -   进程同步与互斥
    -   信号量机制及 P、V 操作
    -   生产者---消费者问题
    -   有界缓冲区（有限缓冲区）管理
    -   多类消费者的条件同步
    -   信号量初值及其含义
-   **题目分值：** 7 分
-   **题目类型：** 综合应用题（同步与互斥、伪代码设计）

## 二、题目条件整理

### 1. 原题

**2009 年第 45 题（7 分）**

三个进程 P1、P2、P3 互斥使用一个包含 N（N \> 0）个单元的缓冲区。

-   P1 每次用 `produce()` 生成一个正整数，并用 `put()`
    送入缓冲区某一空单元中；
-   P2 每次用 `getodd()` 从该缓冲区中取出一个奇数，并用 `countodd()`
    统计奇数个数；
-   P3 每次用 `geteven()` 从该缓冲区中取出一个偶数，并用 `counteven()`
    统计偶数个数。

请用信号量机制实现这三个进程的同步与互斥活动，并说明所定义的信号量的含义（要求用伪代码描述）。

### 2. 已知条件

  ----------------------------------------------------------------------------------------
  条件                                具体内容
  ----------------------------------- ----------------------------------------------------
  进程数量                            3 个进程：生产者 P1、奇数消费者 P2、偶数消费者 P3

  缓冲区容量                          N 个单元，且 N \> 0

  缓冲区使用关系                      三个进程互斥使用同一个缓冲区

  P1 的任务                           每次产生一个正整数，放入缓冲区的某一空单元

  P2 的任务                           每次从缓冲区取出一个奇数，并统计奇数个数

  P3 的任务                           每次从缓冲区取出一个偶数，并统计偶数个数

  同步要求                            缓冲区有空位时生产者才能放入；存在奇数时 P2
                                      才能取；存在偶数时 P3 才能取

  互斥要求                            对缓冲区的访问必须互斥，避免多个进程同时修改缓冲区
  ----------------------------------------------------------------------------------------

### 3. 题目中的操作含义

  操作            含义
  --------------- ---------------------------------
  `produce()`     生产一个正整数
  `put(x)`        将整数 x 放入缓冲区的某个空单元
  `getodd()`      从缓冲区中取出一个奇数
  `geteven()`     从缓冲区中取出一个偶数
  `countodd()`    对取出的奇数进行计数
  `counteven()`   对取出的偶数进行计数

题目没有给出缓冲区的具体存储结构，因此不需要设计数组下标、队列指针等细节。只需按照题意调用相应操作，并用信号量保证同步与互斥。

## 三、逐问解析

本题只有一个综合性设问：设计三个进程的同步与互斥方案，并解释信号量的含义。

### 1. 考查知识点

-   有界缓冲区的生产者---消费者问题；
-   互斥信号量与同步信号量的使用；
-   多个消费者按照数据类型分别等待；
-   P、V 操作的执行顺序。

### 2. 解题思路

本题不能只使用传统生产者---消费者问题中的 `empty` 和 `full` 两个信号量。

原因是：这里有两个不同类型的消费者：

-   P2 只能取奇数；
-   P3 只能取偶数。

如果只设置一个表示缓冲区已有数据的 `full`
信号量，那么无法保证被唤醒的消费者取到自己需要的数据。因此，应分别设置奇数和偶数对应的同步信号量。

本题设置 4 个信号量：

1.  `mutex`：保证三个进程对缓冲区的互斥访问；
2.  `empty`：记录缓冲区中的空单元数量；
3.  `odd`：记录缓冲区中尚未被取走的奇数数量；
4.  `even`：记录缓冲区中尚未被取走的偶数数量。

### 3. 信号量设置及初值

  ----------------------------------------------------------------------------------------------------------------------
  信号量                            初值 类型             含义
  ---------------- --------------------- ---------------- --------------------------------------------------------------
  `mutex`                              1 互斥信号量       控制缓冲区的互斥访问，同一时刻只允许一个进程进入缓冲区临界区

  `empty`                              N 资源计数信号量   表示缓冲区中空单元的数量

  `odd`                                0 同步信号量       表示缓冲区中可供 P2 取出的奇数数量

  `even`                               0 同步信号量       表示缓冲区中可供 P3 取出的偶数数量
  ----------------------------------------------------------------------------------------------------------------------

初值说明：

-   初始时缓冲区为空，因此 `empty = N`；
-   初始时缓冲区中没有奇数和偶数，因此 `odd = 0`、`even = 0`；
-   初始时没有进程占用缓冲区，因此 `mutex = 1`。

### 4. 详细伪代码

#### （1）生产者进程 P1

``` c
semaphore mutex = 1;
semaphore empty = N;
semaphore odd = 0;
semaphore even = 0;

P1() {
    while (TRUE) {
        x = produce();          // 生成一个正整数

        P(empty);               // 等待缓冲区存在空单元
        P(mutex);               // 申请缓冲区互斥访问权

        put(x);                 // 将 x 放入缓冲区

        if (x % 2 == 1) {
            V(odd);             // 放入一个奇数，通知奇数消费者
        } else {
            V(even);            // 放入一个偶数，通知偶数消费者
        }

        V(mutex);               // 释放缓冲区互斥访问权
    }
}
```

**执行过程解释：**

1.  调用 `produce()` 产生一个正整数 x。
2.  执行 `P(empty)`，申请一个空缓冲区单元。如果缓冲区已满，P1 阻塞等待。
3.  执行 `P(mutex)`，申请缓冲区互斥访问权。
4.  执行 `put(x)`，将 x 放入缓冲区。
5.  判断 x 的奇偶性：
    -   若 x 是奇数，执行 `V(odd)`，通知 P2 有奇数可取；
    -   若 x 是偶数，执行 `V(even)`，通知 P3 有偶数可取。
6.  执行 `V(mutex)`，释放缓冲区互斥访问权。

#### （2）奇数消费者进程 P2

``` c
P2() {
    while (TRUE) {
        P(odd);                 // 等待缓冲区中存在奇数
        P(mutex);               // 申请缓冲区互斥访问权

        getodd();               // 从缓冲区中取出一个奇数
        countodd();             // 统计奇数个数

        V(mutex);               // 释放缓冲区互斥访问权
        V(empty);               // 归还一个空缓冲区单元
    }
}
```

**执行过程解释：**

1.  执行 `P(odd)`，申请一个奇数资源。如果缓冲区中没有可取的奇数，P2
    阻塞等待。
2.  执行 `P(mutex)`，申请缓冲区互斥访问权。
3.  执行 `getodd()`，从缓冲区中取出一个奇数。
4.  执行 `countodd()`，统计取出的奇数。
5.  执行 `V(mutex)`，释放缓冲区互斥访问权。
6.  执行
    `V(empty)`，表示缓冲区释放了一个单元，通知生产者可以使用该空单元。

#### （3）偶数消费者进程 P3

``` c
P3() {
    while (TRUE) {
        P(even);                // 等待缓冲区中存在偶数
        P(mutex);               // 申请缓冲区互斥访问权

        geteven();              // 从缓冲区中取出一个偶数
        counteven();            // 统计偶数个数

        V(mutex);               // 释放缓冲区互斥访问权
        V(empty);               // 归还一个空缓冲区单元
    }
}
```

**执行过程解释：**

1.  执行 `P(even)`，申请一个偶数资源。如果缓冲区中没有可取的偶数，P3
    阻塞等待。
2.  执行 `P(mutex)`，申请缓冲区互斥访问权。
3.  执行 `geteven()`，从缓冲区中取出一个偶数。
4.  执行 `counteven()`，统计取出的偶数。
5.  执行 `V(mutex)`，释放缓冲区互斥访问权。
6.  执行 `V(empty)`，表示缓冲区释放了一个单元。

### 5. 信号量的同步与互斥关系

  操作         进程         作用
  ------------ ------------ ----------------------------------
  `P(empty)`   P1           缓冲区满时，生产者阻塞
  `V(empty)`   P2、P3       消费者取出数据后，增加一个空单元
  `P(odd)`     P2           没有奇数时，奇数消费者阻塞
  `V(odd)`     P1           生产者放入奇数后，通知奇数消费者
  `P(even)`    P3           没有偶数时，偶数消费者阻塞
  `V(even)`    P1           生产者放入偶数后，通知偶数消费者
  `P(mutex)`   P1、P2、P3   申请缓冲区互斥访问权
  `V(mutex)`   P1、P2、P3   释放缓冲区互斥访问权

### 6. 正确性分析

#### （1）互斥访问

三个进程在访问缓冲区前都必须执行 `P(mutex)`，访问结束后执行 `V(mutex)`。

由于 `mutex` 初值为 1，且 P、V
操作具有原子性，因此同一时刻最多只有一个进程进入缓冲区临界区，保证了缓冲区的互斥访问。

#### （2）防止缓冲区溢出

生产者在放入数据前必须执行 `P(empty)`。

-   当 `empty > 0` 时，生产者可以申请空单元；
-   当 `empty = 0` 时，缓冲区已满，生产者阻塞；
-   消费者取出一个数据后执行 `V(empty)`，释放一个空单元。

因此，生产者不会向已满的缓冲区继续放入数据。

#### （3）防止消费者取出错误类型的数据

-   P2 必须先执行 `P(odd)`，只有存在奇数时才能继续执行 `getodd()`；
-   P3 必须先执行 `P(even)`，只有存在偶数时才能继续执行 `geteven()`。

生产者根据所生产整数的奇偶性，分别执行 `V(odd)` 或 `V(even)`。

因此，P2 和 P3 只能在相应类型的数据可用时取出数据。

#### （4）避免因空缓冲区而错误取数

初始时
`odd = 0`、`even = 0`。在生产者放入相应类型的数据之前，对应消费者无法通过
P 操作，因此不会从空缓冲区中取数。

## 四、核心考点总结

### 1. P、V 操作的含义

信号量的 P、V 操作也常写作 `wait()` 和 `signal()`：

  操作     其他常见写法   含义
  -------- -------------- ----------------------------------
  `P(S)`   `wait(S)`      申请资源；若资源不足，则阻塞等待
  `V(S)`   `signal(S)`    释放资源；必要时唤醒一个等待进程

注意：

-   P、V 操作必须是原子操作；
-   P 操作可能导致进程阻塞；
-   V 操作可能唤醒等待该信号量的进程；
-   `wait`、`signal` 与 P、V 分别对应，不是两套不同的同步机制。

### 2. 互斥信号量与同步信号量

  ---------------------------------------------------------------------------------------
  对比项目                互斥信号量               同步信号量
  ----------------------- ------------------------ --------------------------------------
  主要目的                保证临界资源互斥访问     保证进程执行的先后关系或资源可用条件

  常见初值                1                        根据初始资源数量或条件确定

  典型操作                `P(mutex)`、`V(mutex)`   `P(empty)`、`V(empty)` 等

  本题对应                `mutex`                  `empty`、`odd`、`even`
  ---------------------------------------------------------------------------------------

注意：信号量的名称和初值不能单独决定它的作用，应结合 P、V
操作所在的位置判断。

### 3. 生产者---消费者问题的通用模型

对于一个容量为 N 的有界缓冲区，基本信号量通常设置为：

``` c
semaphore mutex = 1;    // 缓冲区互斥访问
semaphore empty = N;    // 空缓冲区单元数
semaphore full = 0;     // 已有产品数量
```

传统单类消费者模型：

**生产者：**

``` c
while (TRUE) {
    produce();

    P(empty);
    P(mutex);

    put();

    V(mutex);
    V(full);
}
```

**消费者：**

``` c
while (TRUE) {
    P(full);
    P(mutex);

    get();

    V(mutex);
    V(empty);

    consume();
}
```

本题与传统模型的区别：

传统模型只有一种消费者，使用 `full` 表示缓冲区中已有产品的数量。

本题有两种消费者，必须将 `full` 拆分为：

-   `odd`：缓冲区中奇数的数量；
-   `even`：缓冲区中偶数的数量。

因此，本题可以理解为**一个生产者、两个分类消费者的有界缓冲区问题**。

### 4. 多类消费者问题的通用解题方法

遇到多个消费者分别消费不同类型资源的问题，可以按照以下步骤设计：

1.  **确定互斥资源：**
    找出需要互斥访问的临界资源，设置互斥信号量，通常初值为 1。
2.  **确定资源总量：**
    如果资源数量有限，设置资源计数信号量，并根据初始资源数量确定初值。
3.  **区分资源类型：**
    如果消费者只能消费特定类型的资源，为每一种类型设置对应的同步信号量。
4.  **确定生产者的 V 操作：**
    生产者根据生产的资源类型，执行对应同步信号量的 V 操作。
5.  **确定消费者的 P 操作：** 每个消费者先对自己对应的类型信号量执行 P
    操作，再申请互斥访问权。
6.  **归还资源：** 消费者取走资源后，释放互斥锁，并对资源计数信号量执行
    V 操作。

### 5. 缓冲区相关信号量的数量关系

在本题中，若暂不考虑进程正在执行但尚未完成的操作，则缓冲区中的空单元数、奇数数和偶数数满足：

\[ empty + odd + even = N \]

这里的关系用于理解缓冲区的资源分布。实际并发执行时，信号量的计数还可能受到已执行
P
操作、尚未完成后续操作的影响，因此不应将该等式机械地用于任意执行瞬间的信号量取值判断。

## 五、易错点

### 1. 只设置一个 `full` 信号量

**错误做法：**

``` c
semaphore full = 0;
```

然后让 P2、P3 都执行 `P(full)`。

**错误原因：**

`full` 只能表示缓冲区中存在数据，不能区分奇数和偶数。P2 或 P3
被唤醒后，不一定存在自己需要的数据。

**正确做法：**

分别设置 `odd` 和 `even`，使不同消费者等待不同类型的数据。

### 2. 忘记设置 `empty = N`

缓冲区容量为 N，初始时缓冲区为空，因此空单元数量为 N。

正确设置：

``` c
semaphore empty = N;
```

不能设置为 0，否则生产者初始时就无法向缓冲区放入数据。

### 3. 忘记设置 `odd = 0`、`even = 0`

初始时缓冲区为空，没有奇数和偶数，因此：

``` c
semaphore odd = 0;
semaphore even = 0;
```

如果初值设置为正数，消费者可能在没有对应数据时错误地继续执行。

### 4. P、V 操作顺序错误

生产者的关键顺序：

``` c
P(empty);
P(mutex);

put(x);

V(odd);       // 或 V(even)
V(mutex);
```

消费者的关键顺序：

``` c
P(odd);       // P3 对应 P(even)
P(mutex);

getodd();     // P3 对应 geteven()
countodd();   // P3 对应 counteven()

V(mutex);
V(empty);
```

尤其要注意：

-   生产者先申请空单元，再申请互斥锁；
-   消费者先等待对应类型的数据，再申请互斥锁；
-   访问缓冲区结束后释放互斥锁；
-   消费者取出数据后归还一个空单元。

### 5. 将 `P(odd)` 或 `P(even)` 放在 `P(mutex)` 后面

不推荐这样写：

``` c
P(mutex);
P(odd);
```

如果缓冲区中没有奇数，P2 会在持有 `mutex`
的情况下阻塞。此时生产者无法进入缓冲区放入奇数，可能导致死锁。

正确顺序：

``` c
P(odd);
P(mutex);
```

先确认存在可消费的奇数，再申请缓冲区互斥访问权。

### 6. 消费者取出数据后忘记执行 `V(empty)`

消费者取走一个数据，就释放了一个缓冲区单元。

如果没有执行：

``` c
V(empty);
```

生产者就无法及时获知空单元增加，可能在缓冲区实际上已经有空位时仍然阻塞。

### 7. 混淆 `V(mutex)` 和 `V(empty)`

两者作用不同：

-   `V(mutex)`：释放缓冲区的互斥访问权；
-   `V(empty)`：表示空缓冲区单元数量增加 1。

二者不能互相替代。

本题消费者中推荐写成：

``` c
V(mutex);
V(empty);
```

在本题给定的操作和同步设计下，这两个 V
操作在消费者取出数据后可以交换：即使先执行
`V(empty)`，生产者被唤醒后仍须通过 `P(mutex)`
才能访问缓冲区。但考试中建议保持先释放互斥锁、再通知空位增加的常见书写顺序。

### 8. 把 `countodd()`、`counteven()` 理解成信号量操作

这两个函数是题目给出的计数操作，不是 P、V 操作。

-   `countodd()`：统计已经取出的奇数；
-   `counteven()`：统计已经取出的偶数。

如果计数变量本身还会被多个进程共享访问，则需要另外考虑计数变量的并发保护。但本题没有要求设计计数变量的同步机制，不必额外增加信号量。

### 9. 考场答题检查清单

-   [ ] 是否定义了 `mutex`、`empty`、`odd`、`even` 四个信号量？
-   [ ] 初值是否分别为 1、N、0、0？
-   [ ] P1 是否先申请空单元，再申请互斥锁？
-   [ ] P1 是否根据整数奇偶性执行对应的 V 操作？
-   [ ] P2 是否先执行 `P(odd)`？
-   [ ] P3 是否先执行 `P(even)`？
-   [ ] 两个消费者是否都执行了 `V(empty)`？
-   [ ] 所有缓冲区访问是否都受到 `mutex` 保护？
-   [ ] 是否说明了每个信号量的初值和含义？

**本题核心记忆：一个互斥信号量 `mutex`，一个空位信号量
`empty`，两个分类同步信号量 `odd` 和 `even`。**
