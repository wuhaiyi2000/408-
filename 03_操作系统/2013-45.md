# 2013-45 信号量实现进程同步与互斥（博物馆参观）

## 一、基本信息

-   **一级主要考点：** 操作系统------进程与线程
-   **二级考点：** 信号量机制、P/V
    操作、进程互斥、进程同步、计数信号量、互斥信号量。
-   **题目分值：** 7 分
-   **题目类型：** 同步与互斥应用题

## 二、题目条件整理

### 1. 原题

**2013 年第 45 题（7 分）**

某博物馆最多可以容纳 500
人同时参观，有一个出入口，该出入口一次仅允许一个人通过。参观者的活动描述如下：

``` text
cobegin
参观者进程 i：
{
    ...
    进门；

    参观；

    出门；
    ...
}
coend
```

请添加必要的信号量和 P、V（或
wait()、signal()）操作，以实现上述过程中的互斥与同步。要求写出完整的过程，说明信号量的含义并赋初值。

### 2. 已知条件

  条件             含义
  ---------------- ----------------------------
  最大容纳人数     500 人
  出入口数量       1 个
  出入口通行规则   同一时刻只允许 1 人通过
  参观过程         进门后参观，参观结束后出门
  并发情况         多个参观者进程并发执行

### 3. 需要解决的两个问题

1.  **容量限制：** 博物馆内同时参观的人数不能超过 500 人。
2.  **出入口互斥：**
    进门和出门共用一个出入口，同一时刻只能有一个参观者通过。

## 三、逐问解析

### 本题：设计信号量并写出完整进程过程

#### 1. 考查知识点

-   计数信号量：控制某类资源的可用数量。
-   互斥信号量：保证临界资源同一时刻只能被一个进程使用。
-   P 操作：申请资源；资源不足时，进程阻塞。
-   V 操作：释放资源，并在必要时唤醒等待进程。

#### 2. 解题思路

本题有两种不同的资源约束，需要设置两个信号量。

**信号量一：`empty`，表示博物馆剩余可容纳人数。**

-   博物馆最多容纳 500 人。
-   初始时馆内无人，因此剩余容量为 500。
-   参观者进门前申请一个名额：`P(empty)`。
-   参观者出门后释放一个名额：`V(empty)`。

因此：

``` text
empty = 500
```

**信号量二：`mutex`，表示出入口是否空闲。**

-   出入口一次只能通过一个人。
-   进门和出门都需要使用同一个出入口。
-   因此，进门和出门操作必须互斥。

初始时出入口空闲：

``` text
mutex = 1
```

#### 3. 完整伪代码

``` text
semaphore empty = 500;   // 博物馆剩余可容纳人数
semaphore mutex = 1;     // 出入口互斥信号量

cobegin
参观者进程 i：
{
    ...

    P(empty);            // 申请一个参观名额

    P(mutex);            // 申请出入口
    进门;
    V(mutex);            // 释放出入口

    参观;

    P(mutex);            // 申请出入口
    出门;
    V(mutex);            // 释放出入口

    V(empty);            // 归还一个参观名额

    ...
}
coend
```

#### 4. 为什么 P(empty) 要放在 P(mutex) 前面？

推荐顺序：

``` text
P(empty);
P(mutex);
进门;
V(mutex);
```

原因：

-   `P(empty)` 用于判断博物馆是否还有容量。
-   如果馆内已经有 500 人，新的参观者应当在馆外等待。
-   此时不应该占用唯一的出入口。
-   只有取得参观名额后，才申请出入口。

如果反过来：

``` text
P(mutex);
P(empty);
```

当博物馆已满时，一个准备进入的进程可能持有 `mutex` 并阻塞在 `empty`
上。此时馆内参观者想要出门，也需要申请
`mutex`，就会被阻塞，导致无法释放容量，形成死锁。

因此，**先申请容量名额，再申请出入口互斥权**。

#### 5. 为什么进门和出门都要使用 mutex？

因为题目说的是"出入口一次仅允许一个人通过"，而不是"入口一次只能进入一个人"。

出入口是进门和出门共用的临界资源，因此：

-   进门时需要 `P(mutex)` 和 `V(mutex)`；
-   出门时也需要 `P(mutex)` 和 `V(mutex)`。

不能只给进门操作加互斥，而忽略出门操作。

#### 6. 信号量含义及初值

  ----------------------------------------------------------------------------------------------------
  信号量           类型             含义                                                          初值
  ---------------- ---------------- -------------------------------------------- ---------------------
  `empty`          计数信号量       博物馆剩余可容纳人数                                           500

  `mutex`          互斥信号量       出入口是否可用，保证同一时刻只有一个人通过                       1
  ----------------------------------------------------------------------------------------------------

#### 7. 最终答案

``` text
semaphore empty = 500;   // 博物馆剩余容量
semaphore mutex = 1;     // 出入口互斥信号量

cobegin
参观者进程 i：
{
    ...

    P(empty);

    P(mutex);
    进门;
    V(mutex);

    参观;

    P(mutex);
    出门;
    V(mutex);

    V(empty);

    ...
}
coend
```

其中，`empty` 控制博物馆内参观人数不超过 500 人；`mutex`
保证进门和出门共用的出入口同一时刻只能有一个人通过。

## 四、核心考点总结

### 1. 计数信号量与互斥信号量

  类型         作用                     常见初值
  ------------ ---------------------- ----------
  计数信号量   管理多个同类资源         资源数量
  互斥信号量   保证临界资源互斥访问            1

本题中：

-   `empty = 500`：500 个参观名额。
-   `mutex = 1`：一个出入口。

### 2. P、V 操作的含义

**P 操作（wait）**

申请一个资源：

-   若资源可用，则信号量减 1，进程继续执行。
-   若资源不可用，则进程阻塞等待。

**V 操作（signal）**

释放一个资源：

-   信号量增加或唤醒等待该资源的进程。
-   使其他进程有机会继续执行。

注意：在操作系统教材的信号量模型中，P、V 操作是原子操作。

### 3. 互斥与同步的区别

**互斥：**

多个进程不能同时使用同一个临界资源。

例如本题的出入口：

``` text
P(mutex);
通过出入口;
V(mutex);
```

**同步：**

进程之间按照资源条件或执行顺序协调运行。

例如本题的容量控制：

``` text
P(empty);   // 有空余名额才能进入
...
V(empty);   // 离开后释放名额
```

本题同时涉及互斥和资源数量控制。

### 4. 容量限制类题目的通用模型

若某类资源最多有 N 个：

``` text
semaphore resource = N;
```

使用资源前：

``` text
P(resource);
```

使用完毕后：

``` text
V(resource);
```

例如：

  场景                     信号量      初值
  ------------------------ --------- ------
  博物馆最多 500 人        `empty`      500
  停车场最多 100 辆车      `empty`      100
  机房有 30 台可用计算机   `empty`       30
  只有一个打印机           `mutex`        1
  只有一个出入口           `mutex`        1

### 5. 临界区的判断

临界区是进程中访问临界资源的代码段。

本题中，真正需要互斥保护的是：

``` text
进门;
```

和：

``` text
出门;
```

因为二者都要使用唯一出入口。

"参观"不需要持有
`mutex`，否则一个人在参观时，其他人就无法进门或出门，严重降低并发程度。

## 五、易错点

### 1. 把两个约束误认为一个约束

本题有两个独立限制：

-   馆内人数不超过 500 人；
-   出入口同一时刻只能有一个人通过。

因此需要两个信号量，而不是只设置一个。

### 2. 把 empty 初值设置为 0

`empty` 表示剩余容量，初始时博物馆无人，剩余容量为 500，因此：

``` text
empty = 500
```

如果定义的是 `count`，表示馆内人数，则初值可以是
0，但进入和离开的操作也必须相应改变。

### 3. 只对进门操作加互斥

出门同样要经过唯一出入口，所以出门也必须使用 `mutex`。

### 4. 把参观过程放在临界区内

错误写法：

``` text
P(mutex);
进门;
参观;
出门;
V(mutex);
```

这样会导致参观者在整个参观期间占用出入口，其他人无法通过。

正确做法是：进门后立即释放 `mutex`，参观结束后再重新申请 `mutex` 出门。

### 5. 先申请 mutex，再申请 empty

可能出现容量已满时，进程持有出入口互斥权并等待容量，导致馆内人员无法出门，形成死锁。

正确顺序：

``` text
P(empty);
P(mutex);
进门;
V(mutex);
```

### 6. 忘记出门后释放容量

只有参观者真正出门后，才应该执行：

``` text
V(empty);
```

否则系统会认为已经离开的参观者仍占用名额。

### 7. 考场检查清单

-   [ ] 是否设置容量计数信号量，初值为 500？
-   [ ] 是否设置出入口互斥信号量，初值为 1？
-   [ ] 是否在进门前执行 `P(empty)`？
-   [ ] 是否对进门操作加互斥？
-   [ ] 是否在进门后立即释放出入口？
-   [ ] 是否对出门操作也加互斥？
-   [ ] 是否在出门后执行 `V(empty)`？
-   [ ] 是否避免让参观过程占用出入口？

**本题核心记忆：一个计数信号量控制 500
人的容量，一个互斥信号量控制唯一出入口；进入前申请容量，进出时申请出入口，离开后释放容量。**
