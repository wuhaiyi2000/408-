# 2010-45 位示图管理、C-SCAN 磁盘调度与 Flash 存储

## 一、基本信息

-   **一级主要考点：** 操作系统------I/O 管理
-   **二级考点：** 位示图（Bitmap）、磁盘空闲块管理、C-SCAN
    磁盘调度、寻道时间、平均旋转延迟、扇区传输时间、Flash
    存储器访问特点。
-   **题目分值：** 7 分
-   **题目类型：** 综合应用题

## 二、题目条件整理

### 1. 原题

**2010 年第 45 题（7 分）**

计算机系统采用 C-SCAN（循环扫描）磁盘调度策略，使用 2KB 内存记录 16384
个磁盘块的空闲状态。

（1）说明如何管理磁盘块空闲状态。

（2）单面磁盘转速为 6000rpm，每个磁道有 100
个扇区，相邻磁道间平均移动时间为 1ms。某时刻磁头位于 100
号磁道，沿磁道号增大的方向移动。请求队列为 50、90、30、120，每个请求读取
1 个随机分布的扇区。求读完这些扇区的总时间。

（3）若将磁盘替换为随机访问的 Flash 半导体存储器（如 U
盘、SSD），是否有比 C-SCAN 更高效的调度策略？说明理由。

### 2. 已知条件汇总

  项目                                  条件
  ---------------------- -------------------
  位示图内存空间                         2KB
  磁盘块数量                        16384 个
  磁盘转速                           6000rpm
  每磁道扇区数                        100 个
  相邻磁道平均移动时间                   1ms
  初始磁头位置                    100 号磁道
  初始移动方向                    磁道号增大
  请求队列                   50、90、30、120
  每个请求                 读取 1 个随机扇区

## 三、逐问解析

### 第（1）问：如何管理 16384 个磁盘块的空闲状态？

#### 1. 考查知识点

位示图的概念、空间开销及其在磁盘空闲块管理中的应用。

#### 2. 解题思路

位示图使用一个二进制位表示一个磁盘块的分配状态。可以规定：

-   0 表示磁盘块空闲；
-   1 表示磁盘块已分配。

也可以采用相反的编码方式，但必须保持统一。

#### 3. 详细计算过程

每个磁盘块需要 1 bit，16384 个磁盘块需要：

``` text
16384 bit
```

换算为字节：

``` text
16384 / 8 = 2048 Byte
```

换算为 KB：

``` text
2048 / 1024 = 2KB
```

因此，位示图大小恰好为 2KB，与题目提供的内存空间一致。

操作系统通过扫描位示图查找空闲块。分配磁盘块时，将对应位修改为"已分配"；释放磁盘块时，将对应位恢复为"空闲"。

#### 4. 最终答案

采用位示图管理磁盘块空闲状态，每个磁盘块对应一个二进制位。16384
个磁盘块共需要 16384 位，即 2048B，也就是 2KB。因此，题目给出的 2KB
内存空间恰好可以记录全部磁盘块的空闲状态。

### 第（2）问：采用 C-SCAN 算法，读取请求队列中的扇区总共需要多少时间？

#### 1. 考查知识点

C-SCAN 磁盘调度、寻道时间、平均旋转延迟、扇区传输时间。

#### 2. 解题思路

C-SCAN
的基本思想是：磁头沿一个方向移动，依次服务该方向上的请求；到达磁盘末端后，返回磁盘起始端，再沿原方向继续服务。

磁头初始位于 100 号磁道，向磁道号增大的方向移动。请求队列为：

``` text
50、90、30、120
```

先服务当前方向上的 120 号磁道，再循环到低磁道区域，服务 30、50、90
号磁道。

请求服务顺序：

``` text
120 → 30 → 50 → 90
```

磁盘读取时间由三部分组成：

``` text
总访问时间 = 寻道时间 + 旋转延迟 + 数据传输时间
```

**重要说明：** 严格按照 C-SCAN
定义计算完整寻道距离，需要知道磁盘最大磁道号（磁盘末端位置）。题目没有给出最大磁道号，因此严格的总寻道时间无法唯一确定。下面先计算能够确定的部分，再说明常见简化口径。

#### 3. 计算平均旋转延迟

磁盘转速为 6000rpm，即每分钟旋转 6000 圈：

``` text
每秒转数 = 6000 / 60 = 100 圈/秒
```

旋转一圈所需时间：

``` text
单圈时间 = 1 / 100 秒 = 0.01 秒 = 10ms
```

随机分布的目标扇区平均等待半圈：

``` text
平均旋转延迟 = 10 / 2 = 5ms
```

每个请求的平均旋转延迟为 5ms。

#### 4. 计算一个扇区的传输时间

每个磁道有 100 个扇区，旋转一圈需要 10ms：

``` text
单扇区传输时间 = 10 / 100 = 0.1ms
```

每个请求读取一个扇区，因此每个请求的平均传输时间为 0.1ms。

#### 5. 计算四个请求的旋转延迟和传输时间

共有 4 个请求：

``` text
旋转延迟总和 = 4 × 5ms = 20ms
传输时间总和 = 4 × 0.1ms = 0.4ms
两项合计 = 20 + 0.4 = 20.4ms
```

#### 6. 严格 C-SCAN 的寻道时间

设磁盘最大磁道号为 M，且 M 不小于 120。严格按 C-SCAN
执行时，磁头移动过程为：

1.  从 100 号磁道移动到 120 号磁道；
2.  继续向磁道号增大的方向移动到最大磁道 M；
3.  从磁盘末端返回 0 号磁道；
4.  再依次服务 30、50、90 号磁道。

移动距离分别为：

  移动过程      移动距离
  ----------- ----------
  100 → 120           20
  120 → M        M - 120
  M → 0                M
  0 → 30              30
  30 → 50             20
  50 → 90             40

总移动距离：

``` text
20 + (M - 120) + M + 30 + 20 + 40
= 2M - 10 个磁道
```

相邻磁道平均移动时间为 1ms，因此：

``` text
总寻道时间 = (2M - 10)ms
```

加上旋转延迟和传输时间：

``` text
总时间 = (2M - 10) + 20.4
       = (2M + 10.4)ms
```

由于题目没有给出最大磁道号 M，无法得到唯一的严格数值答案。

#### 7. 常见简化计算口径

部分解答会将 120 号磁道到 30
号磁道的循环过程，直接按两者的磁道号差计算，而不计磁头到达磁盘末端再返回起始端的移动。

按这种简化口径：

  移动过程                       移动距离
  ---------------------------- ----------
  100 → 120                            20
  120 → 30（按循环差值简化）           90
  30 → 50                              20
  50 → 90                              40

总移动距离：

``` text
20 + 90 + 20 + 40 = 170 个磁道
```

寻道时间：

``` text
170 × 1ms = 170ms
```

总读取时间：

``` text
170 + 20 + 0.4 = 190.4ms
```

因此，**如果题目采用上述简化循环距离口径，答案为 190.4ms**。但严格
C-SCAN
还需要知道磁盘末端位置，不能把该简化结果当作无条件成立的严格答案。

#### 8. 本问结论

-   请求服务顺序：120 → 30 → 50 → 90。
-   平均旋转延迟：每个请求 5ms，四个请求共 20ms。
-   扇区传输时间：每个请求 0.1ms，四个请求共 0.4ms。
-   严格 C-SCAN：缺少最大磁道号，无法得到唯一总时间。
-   按简化循环距离口径：总时间为 190.4ms。

### 第（3）问：Flash 是否有比 C-SCAN 更高效的调度策略？

#### 1. 考查知识点

机械磁盘与 Flash
存储器的访问原理、磁盘调度算法的适用条件、FCFS（先来先服务）。

#### 2. 解题思路

传统机械磁盘访问数据时，需要移动磁头并等待盘片旋转到目标扇区，因此寻道时间和旋转延迟是重要开销。C-SCAN
通过优化磁头移动顺序来改善性能。

Flash
半导体存储器采用电子方式访问数据，没有机械磁头，也没有盘片旋转过程，因此不存在传统意义上的寻道时间和旋转延迟。

#### 3. 详细分析

**（1）传统磁盘为什么需要 C-SCAN？**

传统磁盘访问数据需要经历：

-   寻道：磁头移动到目标磁道；
-   旋转等待：等待目标扇区转到磁头下方；
-   数据传输：读取扇区内容。

C-SCAN
通过让磁头沿一个方向循环扫描，减少不必要的磁头往返移动，并使请求等待时间分布相对均匀。

**（2）Flash 为什么不需要 C-SCAN？**

Flash 通过电子方式访问存储单元：

-   没有机械磁头移动；
-   没有盘片旋转；
-   不存在传统意义上的寻道时间；
-   不存在旋转延迟。

因此，传统磁盘调度算法所优化的主要机械开销，在 Flash
存储器中不再以相同方式存在。

**（3）可以采用什么策略？**

可以采用 FCFS（First Come First
Served，先来先服务）策略，按照请求到达的先后顺序处理请求。

其优点是：

-   实现简单；
-   不需要根据磁道位置重新排序；
-   请求服务顺序公平；
-   避免为减少机械寻道而进行不必要的请求重排。

需要注意，现代 SSD
内部仍然存在闪存页、块、通道、垃圾回收、磨损均衡和并行调度等复杂机制。这里的
FCFS 是针对题目所考查的传统磁盘请求调度层面，并不意味着 SSD
内部所有操作都严格采用 FCFS。

#### 4. 最终答案

可以采用 FCFS（先来先服务）策略。

原因：Flash
存储器采用电子方式访问数据，不存在传统磁盘的机械寻道时间和旋转延迟，访问位置对访问时间的影响显著减小。因此，没有必要像机械磁盘那样使用
C-SCAN 优化磁头移动。FCFS 实现简单、公平，能够避免不必要的请求重排。

## 四、核心考点总结

### 1. 位示图（Bitmap）

位示图使用一个二进制位表示一个存储单元或磁盘块的分配状态。

若管理 N 个磁盘块：

``` text
位示图总位数 = N
位示图总字节数 = N / 8
```

如果结果不是整数，需要向上取整。

本题：

``` text
16384 / 8 = 2048B = 2KB
```

因此 2KB 的位示图可以管理 16384 个磁盘块。

### 2. 磁盘访问时间

``` text
磁盘访问时间 = 寻道时间 + 旋转延迟 + 数据传输时间
```

-   寻道时间：磁头移动到目标磁道的时间。
-   旋转延迟：等待目标扇区转到磁头下方的时间。
-   传输时间：实际传输数据的时间。

### 3. 平均旋转延迟

若磁盘转速为 R rpm：

``` text
单圈时间 = 60 / R 秒
平均旋转延迟 = 单圈时间 / 2
```

本题：

``` text
单圈时间 = 60 / 6000 秒 = 0.01 秒 = 10ms
平均旋转延迟 = 10 / 2 = 5ms
```

### 4. 扇区传输时间

若一个磁道有 S 个扇区，旋转一圈时间为 T：

``` text
单扇区传输时间 = T / S
```

本题：

``` text
10ms / 100 = 0.1ms
```

### 5. C-SCAN（循环扫描）

磁头沿一个方向移动，依次处理该方向上的请求；到达磁盘末端后，返回起始端，再沿原方向继续扫描。

特点：

-   请求服务方向固定；
-   具有循环扫描特征；
-   请求等待时间分布通常比普通 SCAN 更均匀；
-   严格计算寻道距离时，需要知道磁盘起始端和末端的磁道位置。

### 6. FCFS（先来先服务）

按照请求到达的先后顺序处理请求。

特点：

-   实现简单；
-   公平性较好；
-   不需要按磁道位置排序；
-   在机械磁盘上可能产生较大的寻道开销；
-   对没有机械寻道和旋转延迟的 Flash
    存储器，传统磁道位置优化的意义较小。

### 7. 机械磁盘与 Flash 对比

  对比项目                   机械磁盘 HDD     Flash（SSD、U 盘）
  -------------------------- ---------------- ---------------------
  访问方式                   机械磁头和盘片   电子方式访问
  是否需要机械寻道           需要             不需要
  是否有旋转延迟             有               无
  访问位置是否明显影响延迟   是               通常小得多
  传统磁盘调度的意义         较大             显著降低
  可采用的简单调度策略       根据场景选择     FCFS 可作为简单策略

## 五、易错点

### 1. 位示图的位数和字节数混淆

16384 个磁盘块需要 16384 位，而不是 16384 字节。

``` text
16384 bit / 8 = 2048 Byte = 2KB
```

### 2. 忘记磁盘访问时间由三部分组成

不能只计算寻道时间，还要考虑旋转延迟和数据传输时间。

``` text
总访问时间 = 寻道时间 + 旋转延迟 + 传输时间
```

### 3. 平均旋转延迟不是一整圈

随机扇区平均等待半圈。本题一圈 10ms，因此平均旋转延迟为 5ms。

### 4. 将 rpm 直接当作每秒转数

6000rpm 表示每分钟 6000 圈：

``` text
6000 / 60 = 100 圈/秒
```

一圈需要 10ms，而不是 1/6000 秒。

### 5. 忘记计算扇区传输时间

每个磁道有 100 个扇区，一圈需要 10ms，因此读取一个扇区需要：

``` text
10 / 100 = 0.1ms
```

### 6. C-SCAN 与 SCAN 混淆

-   SCAN：磁头到达一个方向的末端后，反向扫描。
-   C-SCAN：磁头到达一个方向的末端后，返回另一端，再沿原方向扫描。

C-SCAN
不是简单地将请求队列排序后计算相邻请求的距离；严格计算时还要考虑磁盘末端和返回起点的移动。

### 7. 题目没有给出最大磁道号

严格计算 C-SCAN
的完整寻道距离，需要知道磁盘末端位置。本题没有提供最大磁道号，因此不能无条件给出唯一的严格总寻道时间。

如果采用简化的循环距离计算，才可以得到 170ms 的寻道时间和 190.4ms
的总时间。答题时应说明采用的计算口径。

### 8. 认为 Flash 完全不需要任何调度

Flash
不需要传统机械磁盘那样的寻道优化，但仍然需要处理并发请求、通道资源、垃圾回收、磨损均衡等问题。题目所问的是传统磁盘调度策略是否仍有优势，不能扩大解释为
Flash 内部完全没有调度。
