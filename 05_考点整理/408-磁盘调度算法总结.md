# 408 操作系统：磁盘调度算法考点总结

## 一、磁盘访问时间的组成

机械硬盘访问数据通常包含三个时间：

``` text
磁盘访问时间 = 寻道时间 + 旋转延迟 + 数据传输时间
```

  -------------------------------------------------------------------------------------------
  时间                    含义                               影响因素
  ----------------------- ---------------------------------- --------------------------------
  寻道时间                磁头移动到目标磁道所需时间         磁头移动的磁道数、磁头移动速度

  旋转延迟                等待目标扇区旋转到磁头下方的时间   磁盘转速、目标扇区位置

  数据传输时间            真正读取或写入数据的时间           数据量、磁盘转速、传输速率
  -------------------------------------------------------------------------------------------

磁盘调度算法主要通过安排请求的服务顺序，减少磁头移动距离和寻道时间。它不能直接消除旋转延迟和数据传输时间。

### 1. 寻道时间

若题目给出相邻磁道平均移动时间为 t，磁头总共移动了 d 个磁道，则常用：

``` text
寻道时间 = d × t
```

注意：这是题目给出"每跨越一个磁道需要 t
时间"时的简化模型。真实磁盘寻道时间不一定与磁道距离严格线性。

### 2. 平均旋转延迟

若磁盘转速为 R rpm：

``` text
每秒转数 = R / 60
旋转一圈时间 = 60 / R 秒
平均旋转延迟 = 旋转一圈时间 / 2
```

也就是：

``` text
平均旋转延迟 = 30 / R 秒
```

例如，转速为 6000rpm：

``` text
每秒转数 = 6000 / 60 = 100 圈
一圈时间 = 1 / 100 秒 = 10ms
平均旋转延迟 = 10 / 2 = 5ms
```

随机分布的目标扇区，平均等待半圈，而不是一整圈。

### 3. 数据传输时间

若每个磁道有 S 个扇区，旋转一圈需要 T 时间，则读取一个扇区的传输时间为：

``` text
一个扇区的传输时间 = T / S
```

若连续读取 n 个扇区，且题目允许按连续传输计算：

``` text
传输时间 = n × T / S
```

## 二、四种核心磁盘调度算法

### 1. FCFS：先来先服务（First Come First Served）

**规则：** 按磁盘 I/O 请求到达的先后顺序依次服务。

特点：

-   实现简单，公平性较好。
-   不会因为请求位置而长期推迟某个请求。
-   请求顺序不考虑磁头当前位置，可能造成较大的磁头移动距离和寻道时间。

适用理解：按照请求队列原有顺序计算，不需要排序。

### 2. SSTF：最短寻道时间优先（Shortest Seek Time First）

**规则：** 每次选择距离当前磁头位置最近的请求。

特点：

-   通常能减少平均寻道距离和平均寻道时间。
-   每次选择都要以"当前磁头位置"为基准，服务一个请求后，磁头位置随之改变。
-   可能使远处请求长期得不到服务，产生饥饿现象。

解题方法：

1.  找出距离当前磁头最近的请求。
2.  服务该请求。
3.  将磁头位置更新为该请求所在磁道。
4.  对剩余请求重复上述过程。

注意：不能始终以初始磁头位置计算距离。

### 3. SCAN：扫描算法（电梯调度算法）

**规则：**
磁头沿一个方向移动，依次服务沿途请求；到达磁盘的一端后，改变方向，再服务反方向上的请求。

特点：

-   类似电梯运行，先向一个方向运行，再反向运行。
-   通常比 FCFS 更能减少磁头移动。
-   请求等待时间相对较均匀。
-   磁头到达端点后才改变方向，即使端点附近没有请求，也可能继续移动到端点。

解题方法：

1.  确定磁头初始位置和移动方向。
2.  按当前方向排列并服务沿途请求。
3.  到达题目规定的磁盘端点后反向。
4.  服务另一方向的请求。

### 4. C-SCAN：循环扫描算法（Circular SCAN）

**规则：**
磁头始终沿一个方向服务请求；到达磁盘一端后，快速返回另一端，再沿原方向继续服务。

特点：

-   服务请求时始终保持同一方向。
-   相比 SCAN，等待时间分布通常更均匀。
-   不会在两个方向之间来回服务请求。
-   严格计算物理磁头移动距离时，需要知道磁盘两端的磁道范围。

解题方法：

1.  确定磁头初始位置和移动方向。
2.  先服务当前方向上的请求。
3.  到达磁盘端点后，返回另一端。
4.  再沿原方向服务剩余请求。

特别注意：

-   SCAN 是到端点后反向服务。
-   C-SCAN 是到端点后返回另一端，再按原方向服务。
-   C-SCAN 的"循环"不是把磁头当作在普通数轴上直接反向移动。
-   如果题目或参考答案明确采用"请求序列循环差值"的简化计算口径，应按题目口径计算；若要求严格物理移动距离，则需要磁盘最小、最大磁道号，不能擅自省略到端点和返回端点的移动。

## 三、常见扩展：LOOK 与 C-LOOK

LOOK 和 C-LOOK 是对 SCAN、C-SCAN 的优化理解，复习时要能辨认其规则。

### 1. LOOK

**规则：**
磁头沿当前方向移动，只走到该方向上最后一个请求所在的磁道，就立即反向，不必走到磁盘物理端点。

与 SCAN 的区别：

-   SCAN：通常走到磁盘端点再反向。
-   LOOK：走到当前方向最远的请求处就反向。

### 2. C-LOOK

**规则：**
磁头沿一个方向服务请求，到达该方向最后一个请求后，直接跳到另一端尚未服务的请求处，再沿原方向继续服务。

与 C-SCAN 的区别：

-   C-SCAN：通常移动到磁盘物理端点，再返回另一端。
-   C-LOOK：只在请求范围内循环，不必移动到磁盘物理端点。

## 四、算法对比表

  ------------------------------------------------------------------------------------------------------------------------------------
  算法           选择请求的依据                 是否改变方向                 主要优点                         主要缺点
  -------------- ------------------------------ ---------------------------- -------------------------------- ------------------------
  FCFS           请求到达顺序                   不按固定方向                 简单、公平，不易饥饿             可能寻道距离较大

  SSTF           距当前磁头最近                 不固定                       平均寻道时间通常较小             远处请求可能饥饿

  SCAN           沿当前方向扫描                 到端点后反向                 寻道性能较好，等待较均匀         可能走到没有请求的端点

  C-SCAN         沿单一方向循环扫描             服务方向不反转，端点处循环   等待时间分布较均匀               循环返回会产生移动开销

  LOOK           沿当前方向扫描到最后一个请求   到最远请求处反向             避免无请求时仍走到物理端点       等待时间仍受方向影响

  C-LOOK         沿单一方向循环请求             服务方向不反转               不必移动到物理端点，等待较均匀   循环跳转仍有移动开销
  ------------------------------------------------------------------------------------------------------------------------------------

## 五、磁盘调度题的通用解题步骤

### 第一步：整理已知条件

明确：

-   初始磁头所在磁道。
-   初始移动方向（若题目给出）。
-   请求队列。
-   磁盘最小、最大磁道号（若题目给出）。
-   相邻磁道移动时间或寻道时间计算规则。
-   磁盘转速。
-   每个磁道的扇区数。
-   每个请求需要读取的数据量。

### 第二步：确定服务顺序

根据算法分别处理：

-   FCFS：保持原请求顺序。
-   SSTF：每一步选择距离当前磁头最近的请求。
-   SCAN：沿当前方向服务，到端点后反向。
-   C-SCAN：沿当前方向服务，到端点后循环到另一端。
-   LOOK：到当前方向最后一个请求后反向。
-   C-LOOK：到当前方向最后一个请求后跳到另一端请求。

### 第三步：计算磁头移动距离

将服务过程逐段列出：

``` text
初始磁道 → 第一个请求 → 第二个请求 → ...
```

每段移动距离为两个磁道号之差的绝对值。若算法涉及端点或循环返回，必须根据题目给出的磁盘范围和计算口径处理。

### 第四步：计算寻道时间

``` text
寻道时间 = 总磁头移动距离 × 每跨越一个磁道的平均移动时间
```

仅在题目给出这种线性简化条件时使用。

### 第五步：计算旋转延迟和传输时间

``` text
平均旋转延迟 = 旋转一圈时间 / 2
单扇区传输时间 = 旋转一圈时间 / 每磁道扇区数
```

若每个请求都需要随机等待一个扇区，且有 n 个请求：

``` text
平均旋转延迟总和 = n × 平均旋转延迟
传输时间总和 = n × 单扇区传输时间
```

最后：

``` text
总时间 = 寻道时间 + 旋转延迟总和 + 传输时间总和
```

注意：只有题目要求计算完整磁盘访问时间时，才把三部分全部相加；如果只问磁头移动距离或寻道时间，就不要额外加入旋转延迟和传输时间。

## 六、结合 2010-45 的计算示例

已知：

-   初始磁头位置：100 号磁道。
-   初始方向：磁道号增大。
-   请求队列：50、90、30、120。
-   相邻磁道平均移动时间：1ms。
-   转速：6000rpm。
-   每磁道：100 个扇区。
-   每个请求读取一个随机扇区。

### 1. C-SCAN 请求服务顺序

先服务当前方向上大于 100 的请求，再循环服务低磁道请求：

``` text
100 → 120 → 循环 → 30 → 50 → 90
```

请求服务顺序为：

``` text
120 → 30 → 50 → 90
```

若参考答案采用请求序列循环差值的简化口径：

``` text
100 → 120：20
120 → 30：90
30 → 50：20
50 → 90：40
总移动距离：20 + 90 + 20 + 40 = 170 个磁道
寻道时间：170 × 1ms = 170ms
```

### 2. 平均旋转延迟

``` text
每秒转数 = 6000 / 60 = 100 圈
一圈时间 = 1 / 100 秒 = 10ms
平均旋转延迟 = 10 / 2 = 5ms
四个请求的旋转延迟 = 4 × 5 = 20ms
```

### 3. 扇区传输时间

``` text
一个扇区传输时间 = 10ms / 100 = 0.1ms
四个请求的传输时间 = 4 × 0.1 = 0.4ms
```

### 4. 按简化口径计算总时间

``` text
总时间 = 170 + 20 + 0.4 = 190.4ms
```

说明：这是按该题参考答案所采用的请求序列循环差值口径得到的结果。若按严格
C-SCAN 的物理磁头移动过程计算，还需要磁盘最大磁道号，不能直接把 120 到
30 的循环差值当作完整物理移动过程。

## 七、考研易错点

1.  **SSTF 每次都要更新磁头位置。** 不能始终以初始磁头位置计算最近请求。
2.  **SCAN 与 C-SCAN 不同。** SCAN 到端点后反向；C-SCAN
    到端点后返回另一端，服务方向保持一致。
3.  **LOOK 与 SCAN 不同。** LOOK
    到最后一个请求就反向，不必走到物理端点。
4.  **C-LOOK 与 C-SCAN 不同。** C-LOOK
    在请求范围内循环，不必走到物理端点。
5.  **平均旋转延迟是半圈。** 随机扇区的平均等待时间为一圈时间的一半。
6.  **rpm 要换算单位。** rpm 是每分钟转数，计算秒数时要除以 60。
7.  **不要漏掉传输时间。**
    题目问完整读取时间时，寻道、旋转延迟和数据传输都要考虑。
8.  **不要混淆"寻道距离"和"总访问时间"。**
    只问磁头移动距离时，不需要加旋转延迟和传输时间。
9.  **循环算法要看题目是否给出磁盘端点。** 严格计算 C-SCAN
    的实际移动距离，需要知道磁盘最大、最小磁道号；遇到参考答案的简化口径，要明确其假设。
