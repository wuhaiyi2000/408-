# 408 操作系统：FCB 与 FAT 考点总结

## 一、基本信息

-   **一级主要考点：** 操作系统------文件管理
-   **二级考点：**
    文件控制块（FCB）、目录项、文件元数据、链接分配、文件分配表（FAT）、文件数据块定位、FAT
    与索引分配的区别。
-   **题目类型：** 知识点总结

## 二、FCB：文件控制块

### 1. 基本概念

FCB（File Control
Block，文件控制块）是操作系统用于描述和管理文件的数据结构。

FCB
保存文件的属性和管理信息，使操作系统能够识别文件、查找文件并访问文件。可以把
FCB 理解为文件的"档案"：它描述文件是什么，以及如何找到文件的数据。

### 2. FCB 中常见的信息

  信息类别   典型字段                           作用
  ---------- ---------------------------------- ------------------
  文件标识   文件名、文件标识符                 区分不同文件
  文件属性   文件类型、文件大小、文件状态       描述文件特征
  访问控制   访问权限、用户或所有者信息         控制文件访问
  时间信息   创建时间、修改时间、访问时间       记录文件时间属性
  存储信息   起始块号、索引块地址、文件长度等   定位文件数据
  管理信息   文件链接数、状态标志等             支持文件系统管理

注意：不同文件系统的 FCB 具体字段并不完全相同。现代文件系统中，类似 FCB
的元数据结构可能采用不同名称和组织方式，例如 inode。

### 3. FCB 与目录的关系

目录用于组织和查找文件。目录项通常包含文件名以及指向该文件控制信息的标识或信息。

查找文件的一般过程：

1.  根据路径找到相应目录。
2.  在目录中查找文件名。
3.  通过目录项找到对应的文件控制信息。
4.  根据文件控制信息中的存储信息访问文件数据。

在传统教材模型中，目录项常被理解为包含文件名及对应 FCB
信息；具体实现中，目录项也可能只保存指向独立元数据结构的标识。

### 4. 不同文件分配方式下，FCB 如何定位数据？

  ------------------------------------------------------------------------------------
  分配方式                FCB 中关键的定位信息    如何找到数据块
  ----------------------- ----------------------- ------------------------------------
  连续分配                起始块号、文件长度      由起始块号和块序号直接计算

  链接分配                起始块号、文件长度等    从起始块开始，沿数据块指针逐块查找

  FAT 链接分配            起始簇号、文件长度等    查询 FAT 表项，逐步获得后继簇号

  索引分配                索引块地址              通过索引块中的地址项定位数据块
  ------------------------------------------------------------------------------------

#### 连续分配示例

假设文件 A 从磁盘块 10 开始，占用 5 个磁盘块：

``` text
文件 A：10、11、12、13、14
```

FCB 可以记录：

``` text
起始块号：10
文件长度：5 个磁盘块
```

若目标数据块相对于文件起始位置的序号为 i（从 0 开始），则：

``` text
目标块号 = 起始块号 + i
```

其中 i 必须小于文件占用的数据块数。

#### 索引分配示例

FCB 中记录索引块地址。索引块中保存文件各数据块的地址：

``` text
FCB → 索引块 → 数据块地址
```

因此，FCB 不必直接记录每一个数据块的地址，只需能够定位索引块。

## 三、FAT：文件分配表

### 1. 基本概念

FAT（File Allocation
Table，文件分配表）是一种记录磁盘簇或数据块分配关系的数据结构，也是链接分配的一种典型实现方式。

核心思想：**将文件数据块之间的链接指针集中存放在一张表中。**

普通链接分配把指针放在数据块中；FAT 则把链接关系集中记录在 FAT 表中。

### 2. FAT 表的组织方式

FAT 表通常以磁盘簇号作为表项索引，每个表项记录相应簇的状态或后继簇号。

例如，文件 A 的簇链为：

``` text
10 → 25 → 7 → 30 → EOF
```

对应 FAT 表：

    FAT 表项索引（簇号） 表项内容
  ---------------------- ----------
                      10 25
                      25 7
                       7 30
                      30 EOF

含义：

-   查询 FAT\[10\]，得到下一个簇号 25；
-   查询 FAT\[25\]，得到下一个簇号 7；
-   查询 FAT\[7\]，得到下一个簇号 30；
-   FAT\[30\] 为 EOF，表示文件链结束。

EOF 是示意标记，实际 FAT
文件系统使用特定编码表示文件链结束；空闲簇、坏簇等也有相应的特殊表项值。

### 3. FAT 如何访问文件？

假设目录项或文件控制信息中记录了文件 A 的起始簇号 10。

访问过程：

1.  从目录项中找到文件 A 的元数据。
2.  读取文件的起始簇号 10。
3.  查询 FAT\[10\]，得到 25。
4.  查询 FAT\[25\]，得到 7。
5.  查询 FAT\[7\]，得到 30。
6.  查询 FAT\[30\]，发现文件链结束。

示意：

``` text
目录项 / 文件元数据
        |
        v
   起始簇号 10
        |
        v
FAT[10] = 25
        |
        v
FAT[25] = 7
        |
        v
FAT[7] = 30
        |
        v
FAT[30] = EOF
```

实际读取文件内容时，操作系统根据簇号访问对应的数据区域；FAT
表负责提供簇链关系。

### 4. FAT 的优缺点

**优点：**

-   文件数据块不要求连续存放。
-   文件扩展较方便，只需为文件分配新簇并更新链接关系。
-   链接信息集中存储，便于管理和查找后继簇。
-   FAT 表常驻内存或缓存时，可以减少为读取链接关系而产生的磁盘访问。

**缺点：**

-   FAT 表本身占用存储空间。
-   文件的簇链可能分散，访问文件时可能产生较多磁盘寻道。
-   定位文件中间位置通常需要沿簇链查找，随机访问效率不如索引分配或连续分配。
-   FAT 表损坏可能影响大量文件的簇链访问。

注意：FAT
把链接指针集中到表中，并不意味着它变成了索引分配。其组织逻辑仍然是通过后继指针构成链。

## 四、FCB 与 FAT 的区别和联系

### 1. 核心区别

  对比项目   FCB                                  FAT
  ---------- ------------------------------------ ----------------------------------
  中文名称   文件控制块                           文件分配表
  本质       描述单个文件的控制信息               记录簇或数据块分配、链接关系的表
  管理对象   文件及其属性                         磁盘簇或数据块
  主要内容   文件名、长度、权限、存储定位信息等   簇的状态、后继簇号等
  主要作用   识别、描述和定位文件                 沿文件簇链找到后续数据簇

### 2. 两者如何配合？

以文件 A 的簇链为例：

``` text
10 → 25 → 7 → 30 → EOF
```

文件的目录项或控制信息记录起始簇号 10；FAT 表记录每个簇的后继簇号。

``` text
目录项 / 文件控制信息
    |
    | 文件名、起始簇号 10、文件长度等
    v
  找到文件 A
    |
    v
  查询 FAT 表
    |
    v
10 → 25 → 7 → 30 → EOF
    |
    v
访问对应的数据簇
```

记忆：

-   FCB：描述文件，告诉系统文件从哪里开始以及文件有什么属性。
-   FAT：描述簇链，告诉系统当前簇后面连接哪个簇。

## 五、FAT 与普通链接分配、索引分配的区别

### 1. 普通链接分配与 FAT

  对比项目         普通链接分配       FAT 链接分配
  ---------------- ------------------ -------------------
  指针存放位置     通常放在数据块中   集中放在 FAT 表中
  数据块是否连续   不要求             不要求
  文件组织方式     指针逐块连接       FAT 表项构成簇链
  随机访问         效率较低           通常仍需沿链查找
  管理特点         指针分散           链接信息集中

### 2. FAT 与索引分配

二者都使用表或地址项记录数据块位置，但组织方式不同。

**FAT：**

``` text
当前簇 → 查询 FAT 表项 → 后继簇
```

每个表项记录的是当前簇的后继簇号，形成链式结构。

**索引分配：**

``` text
索引块：
[数据块地址1]
[数据块地址2]
[数据块地址3]
[数据块地址4]
```

索引块直接保存文件各数据块的地址。可以通过索引项直接定位相应数据块，不必从第一个数据块沿链逐个查找。

  对比项目         FAT                            索引分配
  ---------------- ------------------------------ ------------------
  组织思想         链接分配                       索引分配
  表项含义         当前簇的后继簇号               文件数据块的地址
  定位中间数据块   通常沿链查找                   通过索引项定位
  是否需要索引块   不需要传统意义上的文件索引块   需要
  主要开销         FAT 表空间及链式查找           索引块空间

## 六、考研常见考点与判断方法

### 1. 看到"FCB"，想到什么？

-   文件控制信息。
-   文件名、文件长度、权限、时间等元数据。
-   根据文件分配方式记录相应的存储定位信息。
-   查找文件通常先查目录项，再找到相应文件控制信息。

### 2. 看到"FAT"，想到什么？

-   文件分配表。
-   链接分配的一种实现。
-   表项记录后继簇号或特殊状态。
-   文件数据簇可以不连续。
-   通过起始簇号和 FAT 表项逐步追踪文件簇链。

### 3. 看到"文件数据块之间通过指针连接"，想到什么？

链接分配。

如果题目说指针集中存放在一张表中，则通常指 FAT 方式。

### 4. 看到"通过索引块记录文件所有数据块地址"，想到什么？

索引分配，而不是 FAT。

### 5. 看到"起始块号和长度"，想到什么？

这是连续分配的典型定位信息。

## 七、易错点

1.  **FCB 不等于 FAT。** FCB 描述文件；FAT
    记录簇或数据块的分配和链接关系。
2.  **FAT 属于链接分配的实现。**
    不能因为它使用一张表，就把它归类为索引分配。
3.  **FAT 表项记录后继簇号。** 索引块则记录文件各数据块的地址。
4.  **FAT 的数据簇不要求连续。** 文件可能分散在磁盘不同位置。
5.  **FAT 不等于文件内容。** FAT
    保存管理信息，文件实际内容仍存放在数据簇中。
6.  **FCB 的字段与分配方式有关。**
    连续分配通常记录起始块号和长度；索引分配需要记录索引块地址。
7.  **FAT 链式查找不等于直接随机访问。**
    要找到链中较后面的簇，通常需要沿链追踪；缓存 FAT
    可以改善性能，但不改变其链式组织本质。

## 八、考前速记

``` text
FCB：文件控制块，描述文件的属性和存储信息。
FAT：文件分配表，集中记录簇的分配和后继关系。

连续分配：
FCB 记录起始块号和文件长度。
数据块连续，支持高效直接访问。

普通链接分配：
数据块中保存下一个数据块的指针。
数据块可以分散，随机访问效率较低。

FAT：
把链接指针集中存放在文件分配表中。
FAT 表项记录后继簇号。
本质仍是链接分配。

索引分配：
索引块集中记录文件各数据块的地址。
通过索引项直接定位数据块。
```

**核心记忆：FCB 管文件信息，FAT 管簇链关系；FAT
是链接分配的一种实现，不是索引分配。**
